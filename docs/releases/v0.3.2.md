The review hat can inspect files byte by byte, and the plan and review hats can no longer write files through options of "read-only" commands.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What was wrong

The review hat refused `tail -c 50 .gitignore | xxd`, a normal way to check a file's line endings, because `xxd` wasn't on the read-only list.

Checking why turned up a real gap. Some commands already on that list can write files, and the plan and review hats allowed them:
- `sort -o out.txt`
- `uniq in.txt out.txt`
- `tree -o out.txt`
- `find . -fprint out.txt`

The list judged a command by its name, not by how it was used.

## What changed

- **Byte and checksum tools are allowed** in plan and review: `xxd`, `od`, `hexdump`, `strings`, `base64`, `tac`, `rev`, `comm`, `paste`, `sha256sum`, `sha1sum`, `md5sum`, `shasum`, `cksum`.
- **Forms that write a file are refused** in plan and review: `sort -o` (also inside `-no`), `uniq in out`, `tree -o`, `xxd -r`, `xxd in out`, `base64 -o`, and `find -fprint`, `-fprintf`, and `-fls`. The build hat asks before running them.
- **`find -okdir`** is now treated like `-exec`: plan and review refuse it, and the build hat asks.

## Tried before release

In the TUI, in the review hat on `deepseek-pro-latest`, the command that was refused, `cat .dockerignore 2>/dev/null; echo "---GITIGNORE tail---"; tail -c 50 .gitignore | xxd`, ran and returned the hex dump.
