Every question Ryter asks takes the same keys: `Enter` is yes, `Shift+Enter` is yes for the session where that answer exists, `n` is no. Deleting a session and removing a hook are a plain are-you-sure.

## Upgrade

```sh
ryter update
```

Coming from 0.34.0:

- **One answer for every question.** The allow card, the cards asked every time (destruction, a write outside the project, the project's `.env`, a command as root), the plan approval, the audit card, the `/new` question, the trust question, the save-or-discard questions in `/settings` and `/budget`, and the remove questions in `/rules`, `/permissions` and `/hooks` all take `Enter` for yes and `n` for no. The legends say `⏎`, `⇧⏎` and `n`. `y` and `a` still work unsaid.
- **`Shift+Enter` is yes for the session.** On an allow card that offers a session answer ("edits to files in the project", "`cargo test` commands"), a shifted `Enter` gives it. Where the card has no session answer, a shifted `Enter` is a plain yes.
- **Deleting a session asks.** `d` in `/sessions` shows the session's title and id and asks; `Enter` deletes, `n` keeps. There is no id to type. Removing a hook from `/hooks`, a connection from `/provider`, a server from `/mcp` or a skill from `/skills` asks the same way; there is no name or word to type. `x` in `/changes` asks the same question before putting a file back.
- **The trust question is `Enter` or `n`.** The first-run card has no cursor to move: `Enter` trusts, `n` skips, and the body says which is which.
- **The half-second guard stays, and a held key is not a press.** A card that opens under typing ignores an `Enter` that arrives in its first half second, and an `Enter` still held down when that half second ends: a terminal without key-release reports sends a held key as a run of presses, and the card answers only to an `Enter` further than 200 ms from the last. A long rules change still has to be read to its end before `Enter` approves it. The `y`-only rule on the destruction and root cards, which existed for the same moment, is gone.

## Why

The user, after 0.34.0: "all of the asks, they are not consistent across the different areas. Some still ask for y for yes, other say enter. I like enter for yes, shift enter for yes and don't ask again and n for no. Enter should be the consistent yes for all questions." Sixteen questions had five schemes between them. Typing a session's id to delete it was a ceremony for one of the smallest things in the app.

## Good to know

- `Shift+Enter` reaches Ryter as its own key only in a terminal that speaks the kitty keyboard protocol (kitty, WezTerm, Ghostty, foot, recent Windows Terminal), which Ryter asks for at startup. Elsewhere it arrives as a plain `Enter` and allows once; `a` is the session answer there.
- `/yolo` is unchanged. It has answered every ask of the gate yes since 0.14.0, a command as root excepted; what is refused stays refused.
- The `/sessions` panel still lacks the old page's columns, and the README's screenshots still show the previous screen.

## Tried before release

The full local check and CI. The real binary driven offline at 132 columns: a `Shift+Enter` sent as the protocol sends it, on a `git push` card, was recorded as the session answer; `Enter` answered the `/new` question; in `/sessions`, `d` put up the question, `n` kept the session, and `d` then `Enter` deleted it. After the review: an Enter held down across a destruction card's opening left it up, and a press after letting go answered it; the trust card, `/changes` and the three removes answered `Enter` and `n`.
