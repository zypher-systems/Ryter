Mission control's plan is now a drawing: a box per task, in its state's color, joined by arrows to what follows it, as the design showed.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What changed

0.6.0 showed the plan as an indented list, so a design with its two tasks looked like "a plan with 2 subtasks", not a flow. Now:

```
┌────────────────────┐     ┌────────────────────┐
│ ✓ scaffold         │──┬─▶│ ◑ greet            │
│   landed           │  │  │   in audit 0:04    │
└────────────────────┘  │  └────────────────────┘
                        │  ┌────────────────────┐
                        └─▶│ ◐ count            │
                           │   building 0:04    │
                           └────────────────────┘
patch ▸ master  lands when greet, count land
```

- **Each box's border is its state's color:** landed, building, in audit, blocked, waiting, or proposed.
- **What the boxes can't hold is listed under the drawing:** a blocked task's full reason (`✕ scaffold  blocked: … sudo dnf install alsa-lib-devel`), and any extra task it also waits on.
- **A plan too big to draw in the space shows as the list instead,** and a long list keeps its top rows with `… N more rows` rather than losing them.

## Tried before release

In the TUI, on a crew run in a new Rust project, with a scaffold and two tasks after it:
- **Mid-run:** the board drew `✓ scaffold` fanning out to `◑ greet  in audit` and `◐ count  building`, matching the lanes.
- **At the end:** all three boxes read `✓ landed`, and `cargo test` passed all 8 tests on the result.
