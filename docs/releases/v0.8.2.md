When an MCP server stops, Ryter's error now always includes the reason the server gave on its way out.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What was wrong

- **The reason an MCP server gave for stopping could go missing.** Ryter reported the exit as soon as the server's output closed. The last lines the server wrote to its error stream, such as "token expired", could still be on their way. The message then said only that it exited. A CI run of 0.8.1 caught this in Ryter's own test of that message.

## What changed

- **Ryter waits for the server's last words, up to half a second,** before reporting that it stopped. A server that closes its output but keeps running doesn't hold the error up any longer than that.

## Tried before release

- **A new test** has a server close its output, wait a moment, then write "token expired" and exit. Without the wait it fails every time; with it, it passed five runs in a row.
- **In the TUI** with deepseek-v4.1-flash, a test MCP server listed one tool. When called, it closed its output, waited 0.2 s, wrote "token expired" and exited 2. The model found the tool and called it. The tool error read `MCP server fake exited (exit status: 2): token expired`, and the model passed that on.
- **The released 0.8.1 binary, against the same server,** showed only `MCP server fake exited.`, with no exit status and no reason. Its model told the user there was no error from the server, only the notice that it had exited.
