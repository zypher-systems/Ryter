The chat now shows what's happening while Ryter works, and why.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What changed

**The model narrates.** Before each group of actions it says what it's about to do and why. When it chooses between approaches, it says which and why at that moment, not in a summary at the end. When something fails, it says what it thinks went wrong and what it will try next. The crew's lead explains its routing the same way.

For example, from a real run adding SQLite to a todo API:

> Let me check whether the built-in `node:sqlite` works in this Node version before choosing the persistence library.
>
> `node:sqlite` (built-in, zero-dependency) works on this Node. I'll use it rather than a native module like `better-sqlite3`, so there's nothing to compile.
>
> The curl hit a different service: this environment already has an app on port 3000, so that smoke test was contaminated. Let me redo it cleanly on a separate port.

**Every step says what it did,** measured by Ryter, so it's accurate whatever the model reports:

```
 · write  src/store.js                        new · 92 lines
 · write  src/app.js                 rewrote · 76 lines (was 89)
 · edit   .gitignore                                   −0 +1
     + data/
 · run    npm test                               ✓ 13 passed
 ! run    npm run lint                              ✗ exit 1
     npm error Missing script: "lint"
     …
 · look   read 3 files  (test/app.test.js)
 ───── 6 files (3 new, 3 changed, +153 −15) · 9 commands (9 ok) · 2:41 ─────
```

- **Edits** preview the lines that change, without the unchanged lines the model quoted for context.
- **Commands** show ✓ or ✗. Test totals are picked out for node:test, pytest, unittest, Jest, Mocha, and cargo.
- **Failures** show the line that reads like the cause, then the end of the output, inside the row rather than as a separate error.
- **Reads and searches** fold into one line.
- **Every turn that did work ends with a line** listing the files changed, the commands run, and the time taken.

**Also:**

- The hat note Ryter adds for the model (`[hat: build — …]`) no longer shows in your messages when you resume a session.
- A model step that only called tools no longer leaves an empty header.
- File writes report "created" or "rewrote" with line counts, and failed commands report their exit code. The model sees this too.

## Tried before release

2. **SQLite persistence added to it:** 2 minutes 41 seconds, $0.17. It explained its choices as it made them.
