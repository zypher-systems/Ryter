MCP tools no longer hang a turn. A call waits with a deadline, Esc stops it, and each reply is matched to the call it answers. Some servers failed to connect at all before; they connect now.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What was wrong

- **A server that never answered hung the turn for good.** Esc didn't stop it. While it waited, every other MCP tool was blocked too.
- **Ryter took the next line a server wrote as the answer.** A notification, a log line, or a progress update was taken as the result. Every later call then got the answer meant for the one before. A server that sends a notification before it finishes starting couldn't connect at all: the reference test server, `@modelcontextprotocol/server-everything`, showed `error: io: mcp reply: missing field id` in `/mcp`.
- **A tool that failed looked like it succeeded.** When the server marked the result as an error, Ryter passed it on as a normal result.
- **`search_tool` only matched the whole query as one phrase**, and didn't show a tool's arguments, so the model had to guess them.

## What changed

- **Calls have a deadline.** A tool call may run for 120 seconds, and a server has 60 seconds to start. Set `timeout_secs` on a server that needs longer:

  ```toml
  [servers.browser]   # in ~/.ryter/mcp.toml
  command = "npx"
  args = ["-y", "@playwright/mcp"]
  timeout_secs = 300
  ```

- **Esc stops an MCP call at once,** and Ryter tells the server it stopped waiting.
- **Each reply is matched to its call by id.** Notifications, stray log lines, and late replies to abandoned calls are skipped. A server's `ping` gets an answer.
- **One slow server doesn't block the others.**
- **Errors say what happened.** A failed tool call comes back as an error. If a server exits, Ryter names it, with the last thing it wrote to stderr. A timeout names the setting to raise.
- **`search_tool` matches every word of the query,** and lists each tool's arguments.

## Tried before release

In the TUI, on `deepseek-v4.1-flash`, with `@modelcontextprotocol/server-everything` and `timeout_secs = 15`:

1. **`/mcp` in 0.5.5** showed `error: io: mcp reply: missing field id`. **In 0.5.6** it showed `connected · 13 tools`.
2. **With the server's simulated logging on** (a notification every 5 seconds), `echo` and `get-sum` returned `Echo: pong-1` and `The sum of 2 and 3 is 5`.
3. **A 30-second operation** stopped at 15 seconds with `didn't answer tools/call within 15s. If it needs longer, set timeout_secs under [servers.everything] in ~/.ryter/mcp.toml.`
4. **Esc during a 25-second operation** stopped the turn in about 0.2 seconds.
5. **Afterwards, after the abandoned operations had finished,** `echo` and `get-sum` returned `Echo: after-cancel` and `42`.
6. **`search_tool` with "long running operation"** found `trigger-long-running-operation` and listed `duration?: number, steps?: number`.
