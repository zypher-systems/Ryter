The bench is in the binary: `/benchmark` in the TUI, or `ryter bench` from a shell, runs the bench's tasks on your own model and key and tells you tasks solved per dollar; several models run in one go and come back ranked, so the cheapest model with a clean sheet is the one to seat; and four hard tasks join the ten, each turning on a rule the brief states and the visible tests leave alone.

## Upgrade

```sh
ryter update
```

Coming from 0.38.0:

- **`/benchmark` and `ryter bench`.** The bench's fourteen tasks ship inside the binary, so no checkout is needed. The form takes a connection, the models, the tasks (`standard`, `hard` or `all`), a budget and the sandbox; Enter on the models row lists the connection's models with context and prices as `/models` shows them, typing filters, Enter adds or removes one, and models from several connections can sit together. Each task runs in a fresh copy of its project under the build hat as its own `ryter` process with its own session cap, asking nobody anything; the hidden tests are copied in afterwards and run in a bare environment. The panel shows the tasks ticking through with a result, a cost and a time each; `c` closes it while the run goes on, `Esc` asks before stopping after the task in progress. The table lands in `~/.ryter/bench/<date-time>-<model>/RESULTS.md` beside `report.json` and each task's logs. The same run is `ryter bench --level hard --budget 5` from a shell; `--list` names the tasks. The run spends real money on your key: the budget is the cap, with a $0.10 reserve kept back before each task, and a task whose toolchain is missing (`cargo`, `node`) is skipped and says so.
- **Several models compared in one run.** Pick more than one model and they run in turn on the same tasks, each with the budget to itself. The finish is a comparison ranked by tasks solved first and cost second, with a column naming what each model did not solve; the chat line names every model's score and cost. The folder is `<date-time>-compare/` with a folder per model inside and a `RESULTS.md` holding both the ranking and the task-by-task table with a cost in every cell. From a shell, `-m` repeats and `-m connection=model` seats a model on another connection. A cancel stops after the task in progress and skips the remaining models; a model whose own run stops does not stop the next.
- **Four hard tasks.** `expr-precedence` (Python: four precedence levels, a right-associative power, unary minus, errors with the exact message and position), `migrate-dependencies` (Python: a stable dependency order, cycles reported, a run that survives a failure, a state file replaced by rename), `rust-csv-borrow` (Rust: a quoted-field reader whose fields borrow from the input unless they must not, errors with their place) and `ts-debounce` (TypeScript: debounce with leading, trailing and maxWait against an injected clock, and throttle on it). `--level hard` on every runner picks them; the standard ten remain the default. On this level the hard tasks separate models: in the runs made before release, four flash models solved three of four each, three larger models solved one to three, and one solved all four.

## Why

The published number was a cost, measured on this machine with other tools installed. A number is believed when you can make it yourself: on your model, with your key, at your prices, without a checkout. And the question behind it is which model to seat for a kind of work, which is answered by the same tasks run on several models side by side, not by one table. The ten standard tasks measure cost alone, since a current model solves them all, so the hard level was added for the models to differ on.

## Good to know

- The bench never touches your workspace: each task is unpacked to its own copy under `~/.ryter/bench/`, the sandbox confines writes to that copy, and the copies are deleted after scoring. The logs and the report stay. The run leaves your default connection and last model as they were.
- The hidden tests run under the same sandbox, on a copy of the model's tree made only after every process the model started has been ended. On Linux the build hat runs under a leader process that is a child subreaper, so a process that detached from the hat's tree is still under the leader and is ended with the rest; a task whose tree could not be emptied is not scored. On macOS there is no subreaper: a process whose parent exited before the hat ended is not found, and with the sandbox `off` it could read the copy the tests go into.
- tokio moved from 1.53.1 to 1.54.1 for RUSTSEC-2026-0386.
- Ctrl-C on `ryter bench`, or quitting the TUI during a run, ends the task in progress with everything it started and skips the rest; a task cut short, in the model's turn or in its scoring, is not scored, and what it cost still counts in the total. `ryter bench` exits 1 whenever the run did not go to its end.
- The hidden tests travel in the binary deflated and masked, so a model that reads the binary from inside the sandbox does not find them with `grep`. That is a cover, not a secret.
- The hard level's briefs were sharpened twice before release, after nine models in a row read two of ts-debounce's rules the same wrong way; the hidden tests did not change, and a strong model then passed the level in full. What the first runs turned up, and what was fixed, is in `DECISIONS.md` (2026-10-23).
- Headless, the build hat used to be told to answer with its plan when it presented one; it is now told to make the change. A bench or `-p` build run wants the edit.
- A rebuild of the binary under a running `ryter` used to make every bench task fail with "No such file or directory"; the bench now says the binary was replaced and to restart.
- The bench stays head to head on the same tasks. A ranking by language or task kind was considered and set aside: with two Rust and two TypeScript tasks it would be noise.
- Open from earlier releases: the scout has no seat in `/models` and its answer is in the event log only; `max_usd` is checked before a round; the live measurement of check rounds avoided; the `/sessions` panel's columns; selecting with the mouse untried by a person.

## Tried before release

The full local check and CI.
