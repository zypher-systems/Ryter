The host that serves you on OpenRouter is your choice, and shown on every call: press `r` on the OpenRouter row in `/provider` to set the routing rules, `/spend` names the host behind each row, and the lists in `/models`, `/sessions` and the bench keep their columns still while you scroll.

## Upgrade

```sh
ryter update
```

Coming from 0.41.0:

- **Routing rules on the `/provider` screen.** Press `r` on a row OpenRouter serves. The form has every field of OpenRouter's `provider` object as a row, grouped as the order of hosts, what a host must offer, speed, and price, with a line under the focused row saying what it does: `sort` (OpenRouter's choice, price, throughput, latency) and what to sort within, hosts to try first, fallbacks past them, hosts to use only or never, quantizations, every parameter required, data collection, zero data retention, distillable text only, a throughput floor, a latency ceiling as a figure or as `p50=2 p90=5`, and a ceiling in dollars per million for prompt, completion, request and image. `←`/`→` change a choice, Enter types a list or a figure, a clear row puts every rule back, `^s` saves, Esc asks first when you have edits. A figure that cannot be read marks its row and the save waits. The rules go to `~/.ryter/routing.toml`, the connection's row then says the rule in a word (`cheapest host`, `fastest host`, `soonest host`, `host rules`), and the next call carries them without a restart. `r` on a row OpenRouter does not serve says why it does not apply.
- **The same rules in the file.** A `[connections.<name>.routing]` table in `config.toml` takes every field under OpenRouter's own name, and the screen's file lays over it. A closed word or a price below zero is refused at load; host and quantization lists go as written. A routing table on a connection that is not OpenRouter's is refused in `config.toml` and skipped with a warning in `routing.toml`. There is no region field: a region is a segment of an endpoint slug (`baseten/fp8/us`) in the order, only or ignore lists, or a base URL on an OpenRouter business plan. The guide's "Which host serves you on OpenRouter" has the table and the trade-offs.
- **The host on every call.** The host that served each OpenRouter call is read off the stream and kept with the spend record. `/spend` has a row per connection and host (`openrouter · Baseten`), `ryter spend` says `via <host>`, and the bench table names the hosts behind each run. When no host passes the rules, OpenRouter's refusal is said as the step its funnel stopped at (`stopped at: Filter by Max Price`), not as a page of metadata, and points at `r` on the connection's row. The rules set on the screen reach a hat or the scout on another connection in the same session too, not only the session's own connection.
- **Columns that stay put.** The `/models` list, the `/sessions` list and the bench's model picker sized their columns from the rows on screen, so the context, price, reasoning and connection columns jumped as a longer name scrolled into view. They are sized by the whole list now and stay where they are while you scroll or search.
- **Compare: an ablation arm.** `bench/compare.py` takes `ryter@label=connection:model` as a second Ryter arm on the same model and `--ryter-config label=FILE` for that arm's project config, so one piece of the harness can be switched off for one arm and the two compared on the same tasks, model and billing. `bench/ablations/no-map.toml` turns the project map off. The summary gains a "Median rounds" column, each tool's own count of its rounds with the model.

## Why

On a bench run in October 2026, every one of Ryter's calls to GLM 5.3 on OpenRouter landed on a host charging $2.10 per million input tokens while another tool's calls, on the same account and model, landed on one charging $0.08. Neither tool had asked for a host. OpenRouter's own choice is not the cheapest, and until this release Ryter gave you no way to make the choice and no way to see which host you got. The default stays OpenRouter's, since the cheapest hosts serve lossier quantizations; the rules are yours to set, on the screen, in a minute, and the spend rows tell you what they did.

## Good to know

- The `/models` picker lists OpenRouter's plain model ids; a `:floor` or `:nitro` suffix cannot be chosen there. The routing rules do the same job for every model on the connection.
- A `[connections.openrouter]` row of your own in `config.toml` replaces the built-in one whole, so a routing table there needs the full row (base URL, key, default model). The screen's file does not have that cost: it lays over the built-in row.
- The order of the three places: a trusted project's own `.ryter/config.toml` table wins over `~/.ryter/routing.toml` (the screen's file), which wins over `~/.ryter/config.toml`. So a bench arm's `--ryter-config` pin holds whatever the screen has saved, also when it restates the home file's choice; a project row without a `routing` table leaves the rules alone, and an empty table is the project's clear. `routing.toml` is read after `connections.toml` and before the connections are validated; a name it holds that is no connection is skipped. Clearing on the screen saves an empty table for the name, which clears the rules and holds over a table in `config.toml` on the next launch.
- `ryter connections` on the command line does not show the routing rules; the `/provider` row does.
- Open from earlier releases: the scout has no seat in `/models`; the live measurement of check rounds avoided; selecting with the mouse untried by a person; the bench on macOS; lint and format scoped to files; cargo `--test <name>` for a file directly under `tests/`. New: a Ryter-against-another-tool cost table on OpenRouter waits on both tools being pinned to the same hosts; the first person to use the routing screen found it workable but somewhat confusing, and what confused them is not yet known.
