Two patches from the user's first real run on 0.19.0: an expense tracker (Fastify, Vite, Postgres) taken through plan, build, audit, repair and scribe, then dark mode through the same, for $2.67. The flow held, and every hat did its job. What the run showed was how often the gate asked: its 156 shell commands, replayed through 0.19.0's gate, asked 24 times and were refused 5. Through this release's gate they ask 4 times and are refused 2, and three of the four are deletions a live session runs without a card. The one left is `git push`.

## Upgrade

```sh
ryter update
```

From 0.8.2 or earlier, run the install script once:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

Coming from 0.19.0, these behave differently:

- **Deleting a file of the turn's own asks nothing.** `rm -f /tmp/cookies.txt`, or `rm probe.sh` after this turn wrote it, runs in the build and audit hats without a card. Scratch space itself, everything in it, a repository there, your home folder, the project's own files and a file made in an earlier turn ask as before.
- **Naming a secret is not reading it.** `grep '\.env' .gitignore` and `git check-ignore .env` run; `grep KEY .env` is still refused.
- **What `curl` sends as text is text.** A request to the product's own address with a `$(date +%s)` in its body runs.
- **`git remote -v` runs in every hat.**
- **The session log has the asks in it.** `events.jsonl` gains an `asked` line per card, and `at` and `turn` on tool calls. Old logs read as before.

## What was wrong

- Eighteen of the run's twenty-four asks were the model deleting cookie jars in `/tmp` and probe scripts it had written moments before, each behind a `y`-only card that protected nothing the checkpoint did not already hold.
- Three of its five refusals were a secret's name in a `grep` pattern or handed to `git check-ignore`, for a file no command would have printed. One of them ended a twelve-line audit script.
- Fourteen asks were one rule: a `$(date +%s)` inside `curl`'s quoted `-d` data, or a `$ID` inside a `-F` field, read as a path because the value had a dot in it.
- Two asks were a reading bug. The gate had no notion of shell comments, and an apostrophe in a line like `# B's expense list` opened a quote that swallowed the commands after it, so two audit scripts asked for a `curl` of the product that was, read right, a look.
- `git remote -v` asked in the build hat and was refused in the audit, as if it were `set-url`.
- The audit's refusal of `write` said "the audit changes nothing" while its shell commands wrote probe scripts behind the checkpoint all along.
- The log held none of the asks, and tool calls had no turn and no time, so the run's asks had to be reconstructed by replaying its commands through the gate.

## What changed

- **A file of the turn's own is deleted without a card.** Deleting a file or folder of the command's own in scratch space (`rm -f /tmp/cookies.txt`, `find /tmp/probe -name '*.log' -delete`), or a file this turn made (a `write` of a new file, a redirect, `touch`, `cp`, `mkdir`), runs in the build and audit hats without asking: the turn's checkpoint holds neither, so a question protected nothing. `cat > probe.sh; sh probe.sh; rm probe.sh` runs whole. Still asked: scratch space itself or everything in it (`rm -rf /tmp`, `rm -rf /tmp/*`), a repository at or above the path in scratch space, a place the turn moved a file of the user's to, the user's folder, the project's own files, a file made in an earlier turn, and a glob or a value the shell fills in.
- **Naming a secret is not reading it.** A secret's name in a search pattern or a `sed`/`awk` script (`grep -E '\*\.pem|\*\.key' .gitignore`, `sed -n '/\.env/p' .gitignore`), or handed to `git check-ignore` or `git check-attr`, runs in every hat. The file named is still the file read: `grep KEY .env`, `grep -f .env x`, `git show HEAD:.env` are refused as before. A pattern that reads as an absolute path (`grep -o '/assets/[^"]*\.css'`) no longer asks as a read outside the project either.
- **What `curl` sends as text is text.** A `$(date +%s)` inside a `-d` body, a `$ID` inside a `-F` field, a header, a user agent or a `-w` format names no file, so a request to the product's own address with one in it runs. A value that is a file keeps the question: `-d @file`, `-F name=@file`, `-F name=<file`, `--data-urlencode name@file`, `-T`, `-o`, `-H @file`. A body sent to another host asks as before, since it leaves the machine.
- **A comment is not a command.** A `#` that begins a word, outside quotes, runs to the end of its line, as the shell reads it, and a here-document's body keeps its `#` lines, substitutions included.
- **`git remote -v`, `show` and `get-url` are looks.** They print the remotes and run in every hat; `add`, `set-url`, `remove`, `rename`, `prune` and `update` ask in the build hat and are refused in the others, as before.
- **The audit's refusal of `write` says what the audit may do.** It names `audit.md` as the audit's one file, says a probe or a fixture goes through `bash` in the project or `/tmp` and is put back with the checkpoint, and that a lasting change is the build hat's.
- **A session's asks are in its log.** `events.jsonl` has an `asked` line beside each tool call that put a permission card up: the card's title, what it asked, whether only `y` would do, the answer (`allow`, `always`, `deny`, `none`) and how long the person took. Every `tool_call` and `turn_started` line carries `at` (milliseconds since the Unix epoch), and a `tool_call` its `turn`. The same fields are on the `--json` stream. The guide's Sessions section shows a `jq` line that counts a session's asks.

## Tried before release

- **The whole test suite** on Linux: 712 tests pass, with the acceptance suite, both benchmark steps, the install script's test and the licence bundle, each gated on its exit code. New tests cover the free deletions and every line kept around them (scratch root, globs read as written, a repository in scratch, the project's files, the turn boundary), the files a command makes read before it runs, patterns against files for `grep`, `rg`, `sed` and `awk`, `git check-ignore` and `remote`, what `curl` sends as text against what it reads, comments with apostrophes and here-document bodies, and the `asked` event beside its call in the log and on disk.
- **The run's 156 shell commands replayed through the gate** at each step: 24 asks and 5 refusals on 0.19.0, 18 and 2 after the first patch, 4 and 2 after the second. The run's own log shows the three probe deletions left were of files the same turn had made, so a live session runs them. Nothing the run was allowed is refused now; the two refusals left are `sh -c '…'` and `touch /tmp/tls_test.key`, a key-named file.
### Fixed after review

The release PR's external reviews found one failing check and seven ways round the new rules, each shown in bash. Each fix has a test that fails on the reviewed code:

- **The new deletion test failed on macOS.** It filled the turn's made-files list with raw temp paths, while the gate compares resolved ones; on a Mac a temp folder lives behind `/var → /private/var`. The test now records paths the way the agent does. The shipped code was not affected.
- **A tab-indented here-document delimiter ended every body,** where bash strips those tabs only for `<<-`; the `#` line after the false end was then thrown away with the substitution in it. The body now ends only where bash ends it.
- **`)#` was not a comment,** so `(echo hi)# B's list` left an apostrophe to open a quote. A `#` after `)` comments, as after whitespace, `;`, `|`, `&` and `(`.
- **An unquoted variable was one path to the gate** and a glob or two paths to the shell: `F=/tmp/*; rm -rf $F` ran as a free deletion. An expanded operand that still holds `*`, `?`, `[` or whitespace is not free; `rm -f "$F"` with one path in it still is.
- **A part of a command that may not have run still counted as having made a file:** `test -f Cargo.toml || touch decoy` left `decoy` in the turn's list, and a later `mv src/lib.rs decoy && rm -f decoy` would have deleted the user's file. Only a part sure to run when the command succeeds counts: not after `||`, not inside `if`, not in a subshell, and a `&&` chain only when no `||` in the command can hide a failed part.
- **A folder the turn made with the user's file moved into it,** or a scratch path the last copy of a user's file was moved to, was deleted as the turn's own (`mkdir new && mv src/main.rs new/ && rm -rf new`). The places `mv` and `git mv` move a file of the user's to are kept for the turn, and nothing at or under them is a free deletion.
- **Two spellings of the same move were missed on the second round:** `mv --target-directory=new` and `mv -tnew` (the folder attached to its option), and `git -C . mv` (a global option before the verb). Every form of `-t` and `--target-directory`, and `git mv` past any of git's global options, now keep the destination. The third round found the scan took any `t` in a short cluster for the target flag, so `mv -S.txt src new/` (a backup suffix) lost the real destination, and it read past `--`. The cluster is now walked by mv's own letters, `-S` and `-t` taking a value, and nothing past `--` is an option. That rewrite read the raw words and took a trailing `2>/dev/null` for the destination, found by the fourth round; redirects and their targets are the shell's and are skipped, and a here-document or here-string on the move ends the walk, since its delimiter, its word and its body are the shell's too and `mv` reads no input (the fifth round).
- **`awk --source='{print}' .env` read the file:** the program given by `--source` or `-e` was not seen as the program, so the file was taken for the pattern. Both now give the program, and the plain word is the file, read.
- **`rm link` on a project symlink into scratch space ran without a card:** the gate followed the link and saw a scratch path, while `rm` removes the link, a project file the checkpoint holds. The gate now judges the entry `rm` removes and what it points at, both.
