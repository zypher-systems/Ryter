The gate gets out of the way. In the build and test hats the work runs; a question is kept for what no checkpoint undoes, and you can move those questions yourself. Plus `/yolo`, and the tweaks from the first real sessions on the hat rack screen.

## Upgrade

```sh
ryter update
```

From 0.8.2 or earlier, run the install script once:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

Coming from 0.13.0, these behave differently:

- **The build hat edits files without asking.** So do `mkdir`, `cp`, `mv`, `chmod`, `sed -i`, a script in `/tmp` or your home folder, `python3 -c`, and a command Ryter has never heard of. `/undo` still comes back to the checkpoint taken before each build turn. To have edits ask as before, put `edit = "ask"` under `[permissions]` in `~/.ryter/config.toml`.
- **`git commit` runs; `git push` asks.** It was refused outright.
- **`--always-approve` means the same,** and now covers much less, because much less asks.
- **Commands start without `OLDPWD`,** so `cd -` with no earlier `cd` in the same command stays put.

## What was wrong

- **A normal build was a run of questions.** One real session met sixteen command prompts and eleven panel questions in seventeen minutes: an edit, a `mkdir`, a `cp`, a script the model had just written to `/tmp`, a `python3 -c` to look at a value, a `git commit`. Every other harness runs these. The gate was an allowlist, and each session found another spelling it didn't have.
- **It was going to be a rule per program per system.** What counts as a toolchain, a system program or a package manager differs across operating systems and distributions; keeping that list right was a job without an end.
- **The test hat wandered.** `cd -` took it to the folder your shell had been in before Ryter started, and `docker compose up` there started whatever stack it found.
- **The project's `.env` could not be made.** Every hat was refused, so the build hat put the password on each command instead.
- **The prompt sat under the side columns,** the tests row was in two places, and there was no sign of how fast the model was going.

## What changed

- **The build and test hats run the work.** Edits, your toolchains, scripts wherever they are, inline code, system programs, unknown commands, the project's containers and ordinary git run without a question. What asks: deleting (`rm`, `find -delete`, a stack's volumes), throwing work away in git (`reset --hard`, `clean`, `checkout --`, `restore`, `stash drop`), leaving the machine (`git push`, publishing, a `curl` upload to another host, `gh pr create`, `aws s3 sync`, `kubectl apply`, `terraform apply`), writing anywhere but the project, scratch space and your home folder, and the project's `.env`. The guide's "What asks" lists them.
- **What was never allowed still isn't:** reading a secret or a credential folder, `sudo`, a shell handed a command as text, rewiring the shell, a variable that makes a program load something else. The plan, review and test hats still write nothing in the project.
- **Your own rules.** `[permissions]` in `~/.ryter/config.toml`: `edit = "ask"`, and `[permissions.bash]` patterns over a command as it runs, `"rm -rf target" = "allow"`, `"git push*" = "allow"`, `"mv *" = "ask"`, `"cargo publish*" = "deny"`. The most specific pattern wins, the stricter answer at a tie, and a rule is matched against each command of a line. No rule opens a refusal. Rules are read from your file only; a project's config can't widen the gate for itself.
- **`/yolo`,** also `/tools yolo` and `--yolo`: every question is a yes, writes outside the project and the project's `.env` included. What is refused stays refused. `/tools` has the three answers, ask, always and yolo, and `/settings` sets the one a session starts with.
- **The build hat may write the project's `.env`,** asked every time, and may `cp .env.example .env` with a `y`.
- **The test hat uses a compose stack the build hat already brought up** instead of failing on a port in use.
- **A command is read better.** The lines of a here-document are what the command reads, not commands. `$PWD`, `$(pwd)` and `$HOME` are read. `cd ~` is a move, not a write. `cd -` goes back to where the last `cd` of the same command left. A process substitution, `diff <(git show HEAD:f) f`, is a pipe, and the command in it is judged on its own. A shell function is the commands in it. `docker inspect` and `docker compose config` are looks for the hats that may read the project's variables, and a refusal for the rest.
- **After a `cd` out of the project,** a compose or `docker run` command that starts something asks, as a write outside the project does.
- **The review hat** may `GET` the project's own address, list and show the stash, and run the tests with an ordinary variable set (`DB_PASSWORD=x docker compose run app pytest`).
- **A refusal says what it is about:** a secret path, a read outside the project, inline code in a hat that may not run it, each with what to do instead.
- **The screen.** The prompt is the conversation column's width, with the side columns running to the foot. The build and test blocks show checks as three rows, `success`, `warning` and `failure`, with the same words in both. The tests row is gone from the instruments, and a `PULSE` card shows tokens a second with eight seconds of history.

## Tried before release

- **The whole test suite** on Linux: 659 tests pass. The gate's 107 tests were rewritten to the new contract, and new ones cover the user's rules (most specific wins, stricter at a tie, a segment matches, no rule opens a refusal, a project's file can't set them), yolo in the gate and in the tool runner, here-documents, `$PWD` and `$(pwd)`, `cd -`, shell functions, process substitution, container looks from anywhere, and a hidden built-in typed in full.
- **Two real sessions replayed through the gate,** command by command, as they were recorded on 0.13.0. The long one, 130 tool calls, meets 10 questions: four for `.env`, four for `rm` or `down -v`, two in the test hat. The short one, 39 calls, meets 3. On 0.13.0 the first had met sixteen prompts and eleven panel questions in seventeen minutes, with the test hat's wander among them.
- **The TUI in a terminal:** `/yolo` applies and says so, `/tools` shows it current, `/tools ask` turns it off. That run found a fault and it was fixed: `/yolo` is not listed in the palette, and typed in full it was sent to the model as a message.
- **A real session by hand** on the new gate, by the person who asked for it: it gets out of the way.

- **Not yet tried:**
  - `[permissions]` rules in a real session; they are covered by tests only.
  - `--yolo` headless.
  - Anything on a Mac by hand.
