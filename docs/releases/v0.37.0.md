The plan and audit hats can send a question to a scout, a fresh reader whose reading stays out of the conversation; the build hat gets the project's fast check run for it after every round that edited; and a first run starts on the key you exported.

## Upgrade

```sh
ryter update
```

Coming from 0.36.0:

- **The scout.** The plan and audit hats have a `scout` tool: one question about the project, and a fresh model answers it with only the four read tools (`read_file`, `list_dir`, `grep`, `glob`), reading under the asking hat's own gate, so the same secrets are refused. Only its answer enters the conversation, with the paths and lines it rests on, so the hat's context does not fill with files it looked at once. The chat shows one row for the question, `scout  <the question>`, with what it read and what it cost (`✓ 1 read · 1 search · $0.004`); the spend is the asking hat's. It is not a hat: nothing on the rail, nothing to switch to. It runs on the asking hat's model unless `[scout]` in `config.toml` names a connection and a model, which is where a cheap one earns its place; `rounds` (12) and `max_usd` (0.25) cap one question, under the session budget. A failure of the scout's own request (a dropped connection, a model the provider refuses) comes back as the scout's result with what it had, and the hat's turn goes on. The scout's spend is on the asking hat's rows; the context ring, a resumed session's size and the re-reading notice keep to the hat's own calls. The build and scribe hats are refused it and told who has it.
- **The check after edits.** `check` in `.ryter/run.toml` is the project's fast check: `cargo check`, `tsc --noEmit`, `pyright`, `go vet`. In the build hat, after each round in which the model edited files, Ryter runs it itself, shows a `check` row with `✓` or `✗ 2 errors`, and hands the model the errors as the compiler printed them, capped, before its next round, so it does not spend a round running the check and does not skip it. Only a run file you have approved as it stands runs; nothing is asked mid-round. It runs through the same `PreToolUse`/`PostToolUse` hooks as the model's own `run_project` call, and its row is answered however it ends, `cancelled by the user` on Esc included. `run_project` has a `check` action too, and the model is told to propose a check with the rest of the file.
- **A first run starts on the key you exported.** With only `OPENROUTER_API_KEY` set, the quick start used to fail on the built-in default connection without a key. Now a connection that has a key wins over one without: the `--connection` flag as given, then the last-used and the default if keyed, then the first keyed connection in the config. The All hats model named with a connection stays on it, so SpaceXSI's `grok-4.6` is not asked of OpenRouter.
- **The README screenshots show the current screen.** Staged offline against the simulated provider, and `docs/screenshots/HOW.md` says how.
- **The test suite no longer looks a name up in the machine's DNS.** The web guard's test on what a name resolves to hands the resolver in; a box behind a DNS proxy that answers with a benchmarking address no longer fails it.

## Why

An outside gap analysis of 0.36.0 put subagents and LSP at the top of its list and followed the README's quick start to a failure. Reading is where a subagent earns its cost, so the scout reads and nothing is merged. What LSP buys a harness is the model seeing the compiler's errors without a paid round; the run file's check buys the same with nothing to install and no language server running the project's build scripts under the looking hats.

## Good to know

- The scout's answer is in the session's event log, not shown in the chat; the asking hat relays what matters.
- The check's row shows the first lines of each error; the model gets the whole block.
- Owed: a live measurement of check rounds avoided; the simulated bench's model is scripted and cannot show it.
- Open from earlier releases: the `/sessions` panel's columns and its `$0.00` for an unpriced session, the light theme's slab untried by a person, a card not dissolving on closing.
