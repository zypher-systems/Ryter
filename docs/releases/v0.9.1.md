You can now choose the whole crew's models in one visit to `/models`. This is also the first release Ryter can update itself to: on 0.9.0, run `ryter update`, or just start Ryter.

## Upgrade

```sh
ryter update
```

From 0.8.2 or earlier, run the install script once:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What was wrong

- **Choosing the crew's models took a trip per seat.** In `/models`, Enter set the model and closed the panel. Setting the lead, architect, builder and auditor meant opening `/models` four times, and finding the right tab each time.

## What changed

- **`/models` shows the seats beside the list.** On the left are the lead (Solo in solo mode), architect, builder and auditor, each with the model it runs on now. On the right are the models for the seat you've chosen.
  - **Choosing a seat:** ↑↓ picks one. → or Enter moves to its models, and typing starts a filter there straight away.
  - **Setting a model:** Enter sets the model for that seat and takes you back to the seats, on the next one, so a whole crew is pick, Enter, pick, Enter. A ✓ marks each seat you've set.
  - **Other keys:** ← goes back without setting anything, and Esc closes. Tab (reasoning), s (sort) and b (guided crew builder) work as before.
- **The panel is wider,** so long model names fit.

## Tried before release

In the TUI, in crew mode, at 140 columns:
- **One visit to `/models` set all four seats.** I set the lead to deepseek-v4.1-flash, the architect to glm-5.3-prime, the builder to kimi-k3 and the auditor to deepseek-v4-pro. After each Enter, the cursor was back on the seats, on the next one, with a ✓ on the seat just set. When the cursor reached the architect, its list filled with every connection's models. Esc closed the panel, and `crew.toml` held all three roles.
- **Long names:** the first build cut names short (`deepseek-v4.1-fl…`), so the panel got wider. At 80 columns the list drops the reasoning and connection columns to keep model names readable. The line below then leads with the highlighted model's connection and reasoning.

### Fixed after review

The release PR's second external review found three ways the new panel could set or hide the wrong model:
- **→ on the model list moved the highlight to the first row.** On a role, that row is "default (follows the lead)", so → then Enter dropped the role's model. → was the old key for switching roles. Now only a change to the filter's text moves the highlight. →, Home and End just move within the filter.
- **After setting the last seat, its list opened on the model it had before.** Ryter re-read the seat before the change had been applied. Pressing → then Enter would have saved the old model back. Now the list opens on the model you just set.
- **On a narrow screen, the provider was out of sight.** The list drops its connection column when it's narrow, and the line below didn't name the connection. On a role, the connection decides which provider runs it. Now that line leads with the connection and reasoning.

The `/models` description in the command palette and the README no longer mention the old ←→ tabs. Each fix has a test, and all three tests fail on the reviewed code.
