The search provider is set up from the menu. `/provider` has a **web search** row under the connections: choose Tavily, SearXNG or off there, paste the key or type the server's address, and the running session searches with it at once. Nobody has to remember a command or edit a file.

## Upgrade

```sh
ryter update
```

From 0.8.2 or earlier, run the install script once:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

Coming from 0.21.0, these behave differently:

- **The search provider chosen in `/provider` is saved to `~/.ryter/settings.toml`** (`search_provider`, `search_url`) and wins over `[search]` in `config.toml`. A `[search]` you wrote by hand is copied into `settings.toml` the first time any setting is saved from the TUI (a budget, a theme, `/settings`), and from then on `settings.toml` is the one that counts; the row in `/provider` always shows what is in effect.
- **Fields in `/provider` open with their suggested text:** the SearXNG address, and the add-connection wizard's base URL and default model, as they were always meant to. Other panels' fields (`/rename`, `/budget`, `/settings`) still open empty; the hook that fixes them is in place and they are next.

## What changed

- **The search provider has a row in `/provider`.** Under the connections, a **web search** row shows the provider in use and whether its key is in place. Enter on it chooses Tavily, SearXNG or off; Tavily goes straight to the key prompt when no key is stored, SearXNG asks for your server's address with `http://localhost:8080` offered; `k` on the row re-enters the key. The choice is saved to `settings.toml`, and the running session's search is rebuilt at once. The typed `/provider set-key tavily` still works.
- **A `/provider` field starts with the panel's text.** The composer used to clear whatever a panel had set the moment it became that panel's field, so the SearXNG address opened blank and the add-connection wizard's base-URL and default-model suggestions had been lost since they were written. A `prefill` hook on the panel gives the field its starting text; `/provider` uses it, and the same loss in `/rename`, `/budget` and `/settings` is a follow-up.
- **A SearXNG address with credentials in it is refused** (`http://user:pass@host`): it would sit in `settings.toml`, which is not a secret file, and could be echoed in an error.

## Why

The panel showed only model connections, so the one place a person would look for the search key had nothing to offer, and the guide's answer was a command to remember. The user's words: "we need to add that as an option under the menu and not expect users to remember the long form command."

## Tried before release

- **Driven in the real binary,** offline against the simulated provider: the row under the connections, the chooser, Tavily to the key prompt, the panel reopened showing `tavily · no key`, SearXNG to the address field with the local default filled in, and `settings.toml` holding the provider and address afterwards. The blank address field is what the drive caught; the unit test alone had passed.
- **The whole test suite** on Linux: 728 tests pass, with the acceptance suite, both benchmark steps, the install script's test and the licence bundle, each gated on its exit code. New tests cover the row, the chooser's three choices, the address field's prefill and scheme check, `k` on the Tavily row, the settings file carrying the choice and winning over `config.toml`, and the four provider-panel snapshots are regenerated.
- **Not yet tried:**
  - SearXNG live; the audit hat using the search tools with a real model.
  - Anything on a Mac by hand.

### Fixed after review

The release PR's external reviews found one defect and a handful of notes:

- **A failed save left the choice half-applied.** The provider was written into the live config before `settings.toml` was saved, so a save that failed left a choice that any later save (a budget, a theme) would have persisted, while the row and the session still showed the old one. The choice is saved first and applied only on success, as adding a connection already did.
- **Provider spellings.** A hand-written `none`, `off` or `searx` in `[search]` read as "unknown provider" in the row while the search itself accepted them; the row reads them as the search does, and the chooser opens on `off` when no provider is set.
- **Credentials in a SearXNG address are refused** (`http://user:pass@host`), since they would sit in `settings.toml` and could be echoed in an error.
- **Which file wins** is stated plainly here and in the guide: a hand-written `[search]` is copied into `settings.toml` on the first save of any setting from the TUI, and from then on `settings.toml` counts.
