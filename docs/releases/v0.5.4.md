The model picker lists only models you can chat with. Batch routes and image or audio models are gone from it.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What changed

- **No `:batch` models.** A batch route queues the request and answers later without streaming, so it can't answer in a chat. OpenRouter lists about 70 of them.
- **No image or audio models.** Models that make images (such as Nano Banana and GPT-5 Image), music (Lyria), or speech (GPT Audio) have nothing a terminal can show. Where a provider's catalog doesn't give a model's output types, names such as `dall-e`, `gpt-image`, `whisper`, `tts`, and `embedding` are left out instead.
- **Router models stay.** `openrouter/auto` is still listed, even though its catalog entry claims image output. That's because it lists every model it might route to.

This applies everywhere Ryter lists models: `/models`, the `/audit` chooser, and `ryter models`. A model you set by hand in `config.toml` or with `--model` is used as given.

## Tried before release

In the TUI, on OpenRouter:

1. **`/models`** listed 373 models, down from 458.
2. **Searching `batch`, `image`, `audio`, and `lyria`** found nothing.
3. **Searching `openrouter/auto`** found the router, and `v4.1-flash` found the model in use.
