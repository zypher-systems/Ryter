Saving an approved plan can no longer leave a stray file in `.ryter/plans/`.

## Upgrade

```sh
ryter update
```

Coming from 0.44.2:

- **A plan takes its name in one step.** When you approve a plan, Ryter writes it to a temporary file and then gives it its dated name, `-2`, `-3` and on if the name is taken, so an earlier plan is never written over. It used to give the file the new name as a second link and then remove the temporary one. For a moment the file had both names, and if the removal failed the temporary file stayed in `.ryter/plans/` with nothing said. The file now moves into place with a rename that refuses a taken name. The old way remains only on a filesystem that has no such rename.
- **One save no longer removes another's temporary file.** When the link failed for a reason other than a taken name, the temporary name was removed twice. The second removal could hit a file another save had just made under that name.

## Why

The test that has eight savers write the same plan 200 times found 201 files once, on macOS CI. It did not happen again in 760 rounds on the same runner, so the extra file was never seen. The fix closes the only way one could be there, and the test now names any file that was not saved. `DECISIONS.md` 2026-11-07.

## Good to know

- Nothing changes in what is saved or where: `.ryter/plan.md` is the latest approval and the dated copies under `.ryter/plans/` are kept.
- Ryter's other files of its own (`.ryter/run.toml`, `.ryter/decisions.md`, `.ryter/plan.md`) are replaced in place as before; only new names changed.

## Tried before release

The full local check and CI on Linux and macOS. Two external reviews, both approved in the first round with no findings; one also checked that a directory, a link or a fifo already at the name counts as taken. The new rename on GitHub's macOS runner: the plan tests 50 times over and the whole core suite, all passing. One new test: a free name is taken, a taken name or a link there is refused, and no temporary file is left either way. The real TUI with the simulated provider: the same plan approved twice saved as `2026-11-07-kettle-timer.md` and `2026-11-07-kettle-timer-2.md`, nothing else in `.ryter/plans/`, no provider errors.
