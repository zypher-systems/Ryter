A busy model is unmistakable, and the allow card gets out of the reply's way. Both from the first real session on 0.16.0.

## Upgrade

```sh
ryter update
```

From 0.8.2 or earlier, run the install script once:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

Coming from 0.16.0, these behave differently:

- **A turn in progress shows a row under the model's name** with a spinner and what is happening: thinking, writing, running a tool, waiting for the model, or waiting for you. It is gone when the turn ends.
- **The hat's chip in the top bar spins while a turn runs.**
- **The allow card sits inside the conversation column and the chat moves up above it.** Nothing of the reply is covered. The keys are the same.
- **The activity strip is drawn again on the rack screen.** On 0.16.0 the composer was painted over it, so the ticker and the reasoning pane never showed there.
- **A new setting, off by default:** `[ui] bell = true`, or *bell on a question* in `/settings`, rings the terminal once when a card asks you something.

## What was wrong

- **A model that was thinking looked broken.** In a real session the plan model thought on the server for a while and streamed nothing, so the pulse read zero; then the build model reasoned for about twelve thousand tokens before it acted, with nothing in the conversation but a dim strip whose text never changed. The user thought the session had hung.
- **The reasoning pane was empty.** On the rack screen the composer was drawn over the activity strip every frame, so the collapsed ticker and the expanded pane were never visible there, whatever the model streamed.
- **Work landed in a flash.** A model that reasons at length and then emits twenty tool calls in one message had them painted in a single frame, since each write takes milliseconds. The stream was live; the screen did not show it until the end.
- **The allow card covered the reply.** It was docked at the full width of the conversation column, over the chat's last lines, where the eye is not, and it hid what had just been said.

## What changed

- **A live status row** under the current model's header, with the spinner in the hat's color: `thinking · 1:40 · 12k tokens` while reasoning streams, `writing` while text does, `running <tool>` while a tool runs, `waiting for the model · 0:42` when nothing has arrived for three seconds, `waiting for you · allow?` while a card is open. Narrow columns drop the token count, then the elapsed time.
- **The ticker moves.** The collapsed strip shows the tail of what the model is thinking as it thinks, and a tool's label while the tool runs.
- **A waiting state.** After three quiet seconds the strip, the status row and the pane say `waiting for the model`; the pulse card says `waiting` instead of `idle` while a turn is open; the pane says `nothing streamed yet · some models think on the server and send nothing until they answer`.
- **The spinner in the bar,** on the chip of the hat that is on, at every width.
- **Batches of tool calls paint as a sequence.** The screen draws between tool results, so twenty writes arrive as twenty rows.
- **The strip is where it belongs** on the rack screen, between the chat and the composer, with the scrollbar beside the chat.
- **The allow card** is inset in the conversation column, two columns in on each side on a column up to a hundred wide and fourteen in from the left above that, with a heavy top edge in the warn color and a title that names what it asks: `allow? · create templates/item_form.html`. The chat is laid out above it, so the reply's last lines stay visible. The card takes at most a third of the column; a longer change scrolls inside it by the keys and the wheel. The foot line shows the card's keys in the warn color. The keys are unchanged: `⏎` allows after half a second, `a` for the session where offered, `n` or `esc` denies, `y` only for deletion and writes outside the project.
- **A bell, off by default,** for the times you are looking elsewhere when a card opens.

## Tried before release

- **The whole test suite** on Linux: 679 tests pass, with the acceptance suite. New ones cover the status row in each of its states and at narrow widths, the ticker following the reasoning tail, the waiting state after three quiet seconds and back on a delta, the pane's waiting text, the bar's spinner at three widths, the pulse card's `waiting`, the event drain pausing to paint after a tool result; the card's inset at five widths with a square border, the chat moving up with the reply's last line above the card, the height cap, the foot line's colors, the status row's name for each kind of question, and the bell ringing once when on and never when off.
- **In a terminal, against a paced simulated provider** so no model was paid for: five seconds of silence showed the chip spinning, `waiting for the model · 0:04` in the row and the strip, `waiting` on the pulse, and the pane's "nothing streamed yet"; reasoning arriving showed `thinking · 0:07 · 34 tokens` with the ticker moving and the pane filling; six writes arrived as six rows. A write that asks opened the card inset with the whole reply still readable above it, the row reading `waiting for you · allow? · 0:03`, the keys in the foot line; Enter landed the write.

- **Not yet tried:**
  - Any of it with a real model, in the session that reported the problem.
  - The classic layout's foot line does not take the warn color while a card is open; only the rack screen's does.
  - Anything on a Mac by hand.
