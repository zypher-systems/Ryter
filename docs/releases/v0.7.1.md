When a crew task reaches its cap, Ryter asks whether to raise it instead of stopping. A stopped task picks up where it left off instead of paying for the build again. And a task the audit keeps rejecting is counted, and you're told when it needs a stronger builder. Every model, the lead's and each crew role's, is now chosen in `/models`, and `/crew` only switches the mode.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What was wrong

A real crew run spent $9.22 on one UI rewrite and landed nothing:
- **The audit rejected the builder's work 5 times,** and then the task hit its $5 cap. The step it was on had been paid for, and it was thrown away.
- **Retrying a capped task couldn't work.** Its earlier spend still counted against its cap, so a retry paid for one call and stopped again.
- **So the lead recreated the task,** which reset its budget and started the build over: another $2.19, and 3 more rejections.
- **Every retry ran the builder again,** even when all that was left was the audit.
- **The count was wrong.** A task the lead requeued got one more attempt, yet reported "rejected 3 times" each time.
- **Changing a crew model was hidden.** `/crew` switched to crew mode in solo mode, and opened the crew's settings in crew mode. Reaching the builder's model from solo mode took `/crew` twice.

## What changed

- **At its cap, a task pauses and Ryter asks** (`Ryter asks · task budget`). You see what it has spent and on which roles, with three choices:
  - add $5,
  - add $2,
  - or stop, with its branch keeping the work.

  Raising the cap carries the task on from exactly where it was, keeping the step it paid for, and the other workers go on while you decide. A raised cap stays with the task. Runs with no one to ask (headless) stop as before.
- **A task still at its cap asks before it spends anything,** instead of paying for one call that could only stop.
- **A stopped task resumes at the gate.** If its build was committed before it stopped (you stopped it during the audit, the auditor's provider refused, the merge failed), the next run goes straight to the checks and the audit. The builder isn't paid again.
- **The lead is told** to raise the cap and requeue a task rather than recreate it, because recreating it starts the build over.
- **Rejections are counted per task, in all,** across requeues and recreations. The lane card shows them in yellow, and a blocked task says `rejected; blocked (5 rejections in all)`.
- **At 3 rejections, and every 3 after, Ryter tells you to choose a stronger builder** in `/crew → builder`, because more retries of the same model rarely get past the problem. Which model is up to you: Ryter names none and switches nothing. The lead passes the message on without picking one for you, and the cap question mentions it too.
- **Questions Ryter asks** (the task budget, the checks offer) are now titled `Ryter asks · …`, not `the agent asks`.
- **`/models` has a tab per seat:**
  - the lead (`Solo` in solo mode), architect, builder and auditor, with `←→` between them;
  - each tab says what its seat runs on now, and a `used by` column marks which seats use each model;
  - `⏎` sets the model for the seat on screen, `Tab` its reasoning, and `b` opens the guided crew builder.

  It works the same in both modes.
- **`/crew` only switches to crew mode.** A second `/crew` says where the models are. The ready-made and saved crews moved to **`/crews`**.
- **On a role's tab, typing a model's name now filters out the `default` row,** so ⏎ picks the model you typed. Before, `default` stayed pinned above the match and was picked instead.

## Tried before release

In the TUI with your crew (grok-4.7 as lead, minimax-m2.7 builder, qwen3.7-max as architect and auditor) and the task cap set to half a cent, in a small Python project:
- **A one-task build reached the cap.** Ryter asked, with the task's spend by role. Choosing "Add $2" carried the builder on from where it was, and the task landed.
- **Another task was stopped at the cap.** It was blocked, with its branch kept, and the lead said to raise the cap and set it back to pending. Asked to go on, the retry asked before spending anything. Raising the cap let it finish, and it landed. The project's 4 tests pass.
- **The question frame** reads `Ryter asks · task budget`.
- **`/models` in solo mode** opened on the Solo tab at `x-ai/grok-4.7`, marked `lead`. `→` moved to Architect (qwen3.7-max) and then to Builder (minimax-m2.7, marked `build`), each with every model the account can use. Typing `minimax` filtered the list. Your crew file was unchanged.
- **`/crew`** switched to crew mode, a second `/crew` said `/models sets each role's model`, and `/crews` opened the ready-made and saved crews.
