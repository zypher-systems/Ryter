Ryter is a terminal coding agent with two ways to work, in one app.

**Solo mode.** One model works in your project. `Tab` switches its hat: **build** changes your files, **plan** reads and proposes without changing anything, and **review** runs your tests and critiques what changed. Before each build turn changes anything, Ryter snapshots your files, and `/undo` puts them back.

**Crew mode.** Type `/crew` and you talk to a lead instead. An architect designs, builders work in parallel git worktrees, and an independent auditor (a different model from the lead and the builder) signs off each piece before it lands. You get one reviewed commit.

Bring your own keys. OpenRouter and SpaceXAI are built in, and local model servers (Ollama, LM Studio, llama.cpp) work without one. There's no telemetry and no Ryter server: your keys and your code only go to the providers you choose.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

This installs a binary to `~/.local/bin` for Linux (x86_64 and arm64, static, any distro) or macOS (Apple Silicon and Intel). The download is checked against `SHA256SUMS` below before it's installed. To build from source: `cargo install --git https://github.com/zypher-systems/ryter ryter-cli`.

## What's in 0.2.0

- **Solo mode:** build, plan, and review hats. Each hat has its own permission rules in your working tree, and switching never throws away the provider's prompt cache. `/undo` restores your files from the snapshot.
- **Crew mode:** the lead routes every request, with no phases to switch. Independent audit comes before anything lands, and the result is one patch.
- **Crew builder:** a guided setup for the lead, architect, builder, and auditor, with a recommendation and a reason beside each seat. Start from a ready-made crew: **Skiff** (low cost), **Schooner** (balanced), or **Galleon** (high cost). Before saving, each model gets a tiny test request. That catches data-policy settings like OpenRouter's zero data retention, missing tool support, and lack of access or credits, with the reason in plain words.
- **Spend you can see:** every call is priced as it happens. The session total, the project total across sessions (`p` in `/spend`, or `ryter spend --project`), an optional budget (`/budget`, off by default), and a cost estimate by job size in the crew builder.
- **Git handled for you:** an empty folder gets `git init` and a first commit the first time work needs it, with a `.gitignore` that keeps `.env` and keys out. Ryter never does this in your home folder.
- **Headless:** `ryter -p "…"` for one turn, `--hat plan|review|crew` to pick a mode, and `-c` to continue the last session.

## What it costs

From paid runs during development, on an OpenRouter crew (Claude Opus architect, Grok builder, GLM auditor, DeepSeek lead):

- A two-module Python request went to the crew, which skipped the architect and ran two parallel builders. Both were audited and landed as one commit. **$0.15**, about two minutes.
- A three-part command-line app with a design first, 76 tests, landed as one commit. **$1.72**, of which **$0.91** was the architect.
- In solo mode on a budget model, small tasks cost fractions of a cent.

The crew builder's estimates come from these runs. They're rough, and bigger jobs than you expect are the usual surprise, so watch the spend card or set a budget.

## Known limitations

- **The sandbox is Linux-only.** Everything else works on macOS, where the optional Landlock sandbox isn't available. The macOS build is new in this release: it's checked in CI but has seen little hands-on use yet.
- **Windows** isn't supported yet.
- **Headless build mode** needs `--always-approve` to edit files, because nobody is there to approve.
- **`/undo`** restores files, not the side effects of commands (installed packages, databases).
- **The crew is newer than the single-model flow.** It has worked end to end in real runs, but it hasn't yet been benchmarked against a single agent at scale. `ryter bench` exists for that. Results, and reports of where it falls short, are very welcome.
