A repair release. An independent review of 0.11.0 reproduced thirteen defects in secret-file access, file preservation, undo, spending, provider streaming, process cleanup and session recovery. They are fixed here, each with a test, along with the gaps the same review listed.

**Critical: security.** In 0.11.0 a project could have a secret file sent to the model without any tool being asked: a `RYTER.md` or `ROADMAP.md` that is a link to a `.env`, a search over a link to one, or a `.env.production` in a subfolder. Update for those alone.

## Upgrade

```sh
ryter update
```

From 0.8.2 or earlier, run the install script once:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

Coming from 0.11.0, these behave differently:

- **A linked file inside the project is not read.** Instructions, memory, `read_file` and search refuse a link below the project's top, wherever it points. A project whose dependencies are links (a pnpm-style tree) can't be read through them.
- **Credential folders and files are refused inside a project too:** `.ssh`, `.gnupg`, `.aws`, `.azure`, `.kube`, `.netrc`, `.npmrc`, `.pypirc`, `.git-credentials`, `.vault-token` and `.docker/config.json`, at any depth. A project `.npmrc` that only names a registry is refused like one that holds a token.
- **With a budget set, a cancelled or failed request closes the budget.** What that request cost is not fully known, so later requests are refused until `/budget off` or a new session. Esc during a reply does this.
- **A run file's `ready` address must answer 200–399.** A 401 or 404, or HTTPS with a certificate that does not verify, is not ready: the start times out and is taken down.
- **A socket path that is in use is never replaced.** After a crash, delete the old socket file yourself; Ryter says which.
- **Project memory is 48 KB in total,** not per file. A large `ROADMAP.md` can crowd out the other files.
- **The install script needs OpenSSL 3.** A Mac ships LibreSSL: install OpenSSL (Homebrew has it) and set `RYTER_INSTALL_OPENSSL` to it. `ryter update` needs nothing.

## What was wrong

Security and lost work first. All of these are in 0.11.0.

- **A project's instructions could carry a secret into the prompt.** `RYTER.md`, `ROADMAP.md` and the other files Ryter reads at the start were read through links, before any permission was asked and even in a project you had not trusted. A link to a `.env` put its content in the system prompt.
- **Search read what `read_file` refused.** A file that was a link to `.env` was denied to `read_file` and returned by `grep`.
- **A `.env.production` in a subfolder was not a secret.** Only the project's top was checked, so `config/.env.production` could be read in every hat. A `.ssh` or `.aws` folder at the project's top was missed the same way.
- **A mistyped `--socket` path destroyed the file there.** If the path held an ordinary file, Ryter removed it and put a socket in its place.
- **`/undo` failed when Ryter was started in a subfolder of its repository.** Paths were taken from the repository's top and applied from the subfolder: "pathspec did not match".
- **The commit-message draft ignored the budget.** With the budget spent, `d` in `/commit` still called the model.
- **A request that failed or was cancelled lost its cost.** Usage the provider had already reported was dropped, so the session total and the budget read low.
- **A price override with one rate made the other free.** An override naming only the input price counted output tokens at $0.
- **Two unpriced models under a budget were never stopped.** Ryter remembered one model without a price; two taking turns each replaced the other.
- **Parallel tool calls got each other's arguments.** When a model sent two calls and then their arguments in pieces, the pieces were joined to the wrong call. Both calls failed or ran with the wrong input.
- **A start command that failed left what it had started running,** with no record of it for `/stop`.
- **The run file changed the commands in it.** Two spaces inside quotes became one, and line breaks were removed.
- **A status request over MCP could block a cancel** until the turn finished on its own.
- **A session cut off in the middle of a write could not be opened.** One unfinished last line made the whole session unreadable.
- **The context gauge and limit followed the wrong model** when a hat had its own, and a long turn could send more than the model accepts.
- **A noisy command's output was held whole in memory** before being cut to what the model sees.
- **Under a sandbox profile, a command could read other projects' sessions** in Ryter's folder.
- **Two sessions in one repository could damage each other's undo points,** and each other's commit message.
- **The MCP transcript resource returned a session ID,** not a transcript.
- **The install script trusted a checksum downloaded from the same place as the archive.**

## What changed

- **Files and secrets.** Instructions, memory, `read_file` and search share one reader that does not follow a link below the project's top, and one list of secret names that is checked at every depth. Memory is capped at 48 KB in total. Example files (`.env.example`) and public keys (`release.pub.pem`) stay readable. A project's `.docker/` folder is readable and editable; its `config.json` is not.
- **Sockets.** A path that holds anything is left alone, and the error says what to do.
- **Undo and redo** restore from the repository's top and stay within the folder Ryter was started in. Other work, the branch and your staging area are untouched.
- **Spending.**
  - Every request, the commit draft included, passes the same budget check before it is sent.
  - A failed or cancelled request keeps the usage that was reported and marks the session's accounting incomplete. A budget then refuses further requests, after a resume too.
  - A price override with a missing rate is unknown, not free.
  - Every unpriced model is stopped after one call under a budget.
- **Tool calls** keep their identity while streaming on all three protocols (chat completions, Messages, Responses). Where a provider sends every call under index 0 with its own ID, as Ollama does, the ID decides.
- **Starting and stopping a project.**
  - Run commands are kept as written.
  - A failed start takes down what it started and runs the approved stop command; a cleanup that fails is remembered, and `/stop` retries it after a resume.
  - Ready means HTTP 200–399, and an address already in use is not taken for the project.
- **MCP.** Status and spend answer from a snapshot while a turn runs, cancel always gets through, a second prompt during a turn gets "busy", and the transcript resource returns the active conversation (the latest messages, up to 64 KiB).
- **Sessions.** A torn last record is cut off on resume, the original file is kept beside it, and the chat says so. Damage in the middle of a file still stops with an error and changes nothing.
- **Context.** The limit and the gauge follow the hat's own model and count tool schemas and room for the answer. A request too large for the model stops with a message before it is sent.
- **Output.** A command's output is kept as a fixed head and tail while it runs. File reads and search stream, and say what they left out.
- **Sandbox.** Each tool call, hook, Git operation and run command gets a scope with this session's notes and pages only. Git hooks and filters run inside it, including the commit made from `/commit`.
- **Git.** Each undo point and commit message uses its own private scratch folder.
- **Installing.** The install script checks the release signature with the same pinned key as the updater before it trusts the checksums. Release archives carry their dependencies' license notices.
- **The guide and README** describe the four hats, and what runs without a question, as the product does.

## Tried before release

- **The whole test suite** on Linux and macOS: 619 tests pass. Each of the thirteen defects was first reproduced by a test that failed on 0.11.0.
- **A full session against a stand-in provider:** a plan approved, built, reviewed, tested with an approved run file, resumed, undone and redone, edited by hand afterwards and committed with its receipt, from a subfolder of a repository.
- **Seven command-line scenarios** with real subprocesses: each hat, a budget stop, an interrupted request's accounting, and recovery of a torn session.
- **The install script against five local signed fixtures:** a good release installs; a changed archive, a bad or missing signature and a linked executable leave the installed program as it was.
- **Ten small tasks with a real model** (`qwen/qwen3-coder-flash` on OpenRouter, under the `workspace` sandbox, plan to test in each): $0.42 of a $5 limit over 524 requests, every one fully accounted.
  - Six of the ten results passed tests the model never saw. Five went through all four hats with a passing review and test.
  - **Three wrong results were passed by both the review hat and the test hat.** On this model, a passing review is not evidence the work is right. The details are in `docs/acceptance-2026-10-02.md`.
- **The commit panel under the `workspace` sandbox,** in the TUI with no provider connected: `/commit` made the commit, a `pre-commit` hook ran, and the hook could not read a key file in Ryter's folder. The same hook run outside the sandbox read it.

### Fixed after review

The release PR's first external review rejected it for three defects the repairs had introduced. Each fix has a test that fails on the reviewed code:

- **Parallel calls sent under one index were merged.** Ollama sends every parallel call as index 0 with its own ID; keyed by index alone, two calls became one with both arguments joined.
- **A project's `.docker/` folder was refused in every hat,** so a project that keeps its Dockerfiles there could not be worked on.
- **The commit made from `/commit` ran outside the sandbox,** and so did its hooks.

A later review found the two-unpriced-models gap above. It was already in 0.11.0, and is fixed here.

- **Not yet tried:**
  - A whole session in the TUI by a person, with a real model, on a real project.
  - Anything on a Mac by hand. The tests run there; the product was not used there.
  - `/commit` under a sandbox profile with a provider connected. A test covers it; the TUI run above had none.
  - Ollama's parallel calls against a real Ollama. The stream shape comes from its issue tracker.
  - The stricter ready check against a real container.
