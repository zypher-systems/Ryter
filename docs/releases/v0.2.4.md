The build hat can now ask to work outside your project, instead of being refused without a question.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## Writing outside the project

Before this release, the build hat's file tools and shell redirects were refused outright for any path outside the project, such as a scratch file in `/tmp`. They weren't asked about, while a command that created a folder there did ask.

Now a write outside the project, whether a file edit, a redirect, or a command such as `mkdir` or `python3 -m venv`, asks every time:

- **The prompt says "outside the project"** and shows the path. It offers only `y` (allow once) or `n`.
- **"Allow all" and `--always-approve` don't cover these writes.** They apply to your project, not the rest of your machine, so headless refuses them.
- **Some places are refused, however they're asked for.** Credentials (`~/.ryter`, `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.config/gh`, …) and secret files are never read or written. Shell startup files (`~/.bashrc`, `~/.zshrc`, `~/.profile`, …) and system folders (`/etc`, `/usr`, …) are never written. A path spelled with `~`, `$HOME`, or `../..` is recognized the same way.
- **Reading outside the project** (`ls /tmp`, `cat /etc/os-release`) is an ordinary question.
- **Nothing changes elsewhere:** the plan and review hats still never write outside, and crew builders stay in their worktrees.

The message for refused inline code (`python - <<EOF`) no longer sounds like a rule about where code runs. It's about code the gate can't read.

## Tried before release

In the TUI, the build hat was asked to write and run `/tmp/ryter-demo/hello.py`:

1. The write asked with the outside-the-project warning.
2. `a` did nothing.
3. After `y`, the file was written.
4. Running it asked too, and printed its output.
5. The turn finished in 25 seconds.
