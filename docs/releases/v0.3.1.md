The review hat can run your tests when the app is in a subfolder, and when the command sends errors to the output with `2>&1`.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What was wrong

The review hat refused `cd app && npm test 2>&1 | tail -25` with "the review hat can't run commands that change things". Two rules in the permission gate were at fault:

- **`cd` wasn't allowed** in the hats that can't change files (plan and review), or for the crew's auditor, lead, and architect.
- **`2>&1` was misread.** The gate treated the `&` as a command separator, which left a "command" named `1` that it didn't recognize. So even `cargo test 2>&1`, with no `cd`, was refused. A common way to run tests didn't work in review.

## What changed

- **`2>&1`, `>&2`, and `&>/dev/null` are allowed.** They only reroute output. `&>out.txt`, `>&out.txt`, and `&>>log` are now recognized as writing files. The plan and review hats refuse those, as they refuse every file write.
- **`cd` into a folder of your project is allowed** in plan and review, and for the crew's lead, architect, and auditor. Every command after the `cd` is checked from that folder, so a symlink there that points outside the project is still caught. A `cd` out of the project, or a bare `cd` (which goes home), is still refused.
- **The build hat is unchanged.** It still asks before a `cd`.

## Tried before release

In the TUI, in the review hat on `deepseek-pro-latest`, with the app in `app/` and a bug planted in it:

- `cd app && npm test 2>&1 | tail -25` ran.
- The reviewer followed up with more `cd app && npm test 2>&1 | grep …` commands, all allowed.
- It found the bug: 4 failing tests, with their expected and actual values.
