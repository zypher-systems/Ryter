Easier to start, easier to review, cheaper to run: a first run with no key opens the provider list by itself, `/changes` drops one change of a file at a time, and the bench now compares Ryter with other coding agents by tasks solved per dollar, with two published runs.

## Upgrade

```sh
ryter update
```

Coming from 0.37.0:

- **Tasks solved per dollar.** `bench/compare.py` gives the bench's ten tasks to Ryter and to the coding agents installed on the machine (Claude Code, Codex, OpenCode, Kilo), each in a fresh copy of the same project with the same brief, each run so that it asks nobody anything, each scored by the hidden tests and costed by what the tool itself reports. Two runs are published under `docs/bench/` and summed up in the README: on `claude-opus-5-5` all three of Ryter, Claude Code and OpenCode solved all ten, for $0.73, $2.42 and $1.17; on `mistralai/mistral-large-4-0` through OpenRouter, Ryter, OpenCode and Kilo each solved nine, for $0.30, $0.52 and $0.41. Claude Code's figure is its own estimate at list prices and is marked so; a second Opus pass the next day came within three percent per tool. One budget for the whole run, a reserve before each task, one attempt per task; `--dry-run` prints the commands and calls nothing, `--into` runs one tool again into an earlier report.
- **`/changes` drops one change at a time.** A file's diff is shown taken apart change by change, as the chat shows an edit: each change under a heading that says which it is and the lines it covers, highlighted like the file. `←→` picks a change; `x` drops that change alone after the one question, Enter yes and `n` no, keeping the file's other changes; `X` puts the whole file back, which `x` used to do. Ryter snapshots first, so `/undo` brings a dropped change back, and the chat says which change went back. A binary file, or one that is gone, has nothing to take apart, so `x` there asks about the file.
- **A first run with no key opens `/provider` by itself.** With no key on any connection, the TUI opens the provider list before anything else and says in the chat what to do: pick a connection, press `k`, paste the key, or export one of the well-known variables and start again. With a key on any connection nothing opens, and the session starts on a keyed connection as 0.37.0 made it.

## Why

After 0.37.0 the question was what Ryter needs to be noticed. A claim about cost is not noticed without a number against the tools people already use, so the bench got a comparison runner and the README got the number. Reviewing an agent's work change by change before keeping it is the thing people show each other in the other tools, and Ryter had it only by file. And a new user's first screen was a session with a warning line and nothing that could answer.

## Good to know

- The bench's tasks are small and a current model solves them all, so the published number is cost, not ability. Harder tasks are the next step.
- A comparison run spends real money on every tool you name, under one budget; each tool runs as you have it set up, and no key is read or copied by the runner.
- `/changes` no longer shows `r` in its legend, to fit; `r` still reads the files again.
- Open from earlier releases: the scout has no seat in `/models` and its answer is in the event log only; `max_usd` is checked before a round; the live measurement of check rounds avoided; the `/sessions` panel's columns; the light theme's slab untried by a person.

## Tried before release

The full local check and CI. The two published comparison runs, made with the runner on this machine against Claude Code 2.1.309, OpenCode 2.0.28 and Kilo 7.8.12 as installed, plus a second Opus pass. The real binary driven offline: a build turn edited a file in two places, `/changes` showed both changes, the second was dropped alone, the file on disk kept the first, the chat said `put back change 2 of config.rs` and a checkpoint was recorded; and a start with no key on any connection opened the provider list with every connection marked `no key` and the line above saying what to do, with nothing sent to any provider.
