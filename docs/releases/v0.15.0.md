Three hats. The test hat is removed: plan, build and review do the work, and the build hat starts and tests the product itself. Plus the fixes from the first real session on 0.14.0, and a palette that no longer runs a command you didn't type.

## Upgrade

```sh
ryter update
```

From 0.8.2 or earlier, run the install script once:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

Coming from 0.14.0, these behave differently:

- **There is no test hat.** `Tab` goes plan, build, review, and round. `/test` says so and does nothing else. A session that was left in the test hat opens in build. Its event logs, spend and transcripts still load; what the tester did counts under build in the hat rack.
- **The build and review hats start and test the product.** `propose_run` and `run_project` are theirs now; the plan hat is refused them. The run file (`.ryter/run.toml`) and your approval of it are unchanged, and `/stop` still stops what Ryter started.
- **A review is no longer followed by the offer of a test.** The *offer tests* setting is gone; an old settings file with it still loads.
- **A slash word that is no command runs nothing.** It used to go to the model as a message. Now Ryter says "unknown command" and leaves it there.

## What was wrong

- **The test hat did not work for most products.** It was built around a product with an address: start it, wait for `ready`, use it over HTTP, stop it. A terminal app, a desktop app or a game has no address. In the first real session on 0.14.0, a pygame game, the tester made 69 tool calls across two turns, most of them refused or looping, and filed no report.
- **Its one distinction was what made it fail.** The test hat differed from the build hat in one way: it could not change the project. Keeping that promise was an enumeration of every program that edits a file in place, which two review rounds had to extend and a reviewer could still extend further. When the tester met that wall it hunted for a way round instead of testing.
- **Three faults in that session were Ryter's, not the hat's.** A wrapper in front of a program named by a path, `timeout 60 .venv/bin/python x.py`, was refused in the build and test hats: the interpreter's own path was read as a file, and the link under `.venv` points at a system place. A `stop` of `pkill -f name` killed the shell running it; Ryter read the signal as a failed cleanup and refused every start after it, with no way out. A failed scenario reported without a `got` line was sent back twice, and the turn ended with nothing for the user.
- **Typing `/test` stopped the product.** The palette matched `/stop` through its description ("the project Ryter started for a test") and Enter ran it.

## What changed

- **Three hats: plan, build, review.** The top bar names three, the hat rack has three blocks, `Tab` goes round three. The second conversation the tester worked in is gone with it: one transcript a session. The gate's tester rules are gone too, several hundred lines of them.
- **The build hat runs the product.** It proposes the run file, you approve it, and `run_project` starts the product, runs its tests and stops it, as the tester did. The review hat may run the project's tests the same way. A product left running is remembered across sessions as before.
- **A wrapped program named by a path runs.** `timeout`, `nice`, `env` and the like in front of `.venv/bin/python` or any other path no longer make the gate read the program as one of its files.
- **A stop that ends its own shell has stopped the product.** `pkill -f name` matches the shell running it; Ryter now takes that as the stop working. A proposed run file whose `pkill -f` pattern would match itself is refused with the fix, `[n]ame`. A stop command corrected in the run file after a failed cleanup is the one the retry uses.
- **A slash word that is no command runs nothing.** A palette match reached only through a command's description runs on Enter only when you moved the highlight onto it. Otherwise the word is run by name, which says "unknown command". A line starting with a slash is never sent to the model.
- **A refusal in the hats that don't write says what it refused,** instead of claiming a write when the gate refused for another reason.

## Tried before release

- **The whole test suite** on Linux: 639 tests pass, and the acceptance suite's seven. The tester's tests went with the hat; the run file's tests run in the build hat now. New ones cover the wrapped program, the self-killing stop, the pkill pattern check, and the palette rule.
- **The TUI in a terminal:** three hats in the bar and the rack, `Tab` round them, `/test` and an unknown command each saying so and doing nothing. That run found the palette fault, and it was fixed: typing `/test` stopped a product that an earlier session had left running.
- **The tester's refused commands from the real session replayed through the gate:** every one runs now in the build hat except the two that should not, a copy into the project's `.ryter` folder and a detached `nohup`.

### Fixed after review

The release PR's two external reviews rejected it, for four defects. Each fix has a test that fails on the reviewed code:

- **The acceptance suite still sent the test hat,** which the binary refuses, so CI was red. It sends plan and review.
- **The wrapper fix went too far.** Skipping every word before the program also skipped what a wrapper is given: `strace -o ~/.ssh/id_rsa`, `time -o ~/.bashrc`, `xargs -a`, `flock file` ran in the build hat. Only the program's own word is skipped now.
- **The system prompt still had the test hat** and told the model to end with a tool that no longer exists. It describes three hats and how the build and review hats run the product.
- **The palette rule broke aliases.** An alias match has no highlight in the name, so `/perm` and `/conn` stopped running on Enter, and a list of one could never be confirmed. A match is held back only when it came through a description alone, and moving the highlight onto it, in a list of one too, confirms it. A new filter starts the highlight over.

Also from the reviews: a `pkill -f` pattern in quotes is read whole, and the stale name of the plan-hat refusal is gone.
