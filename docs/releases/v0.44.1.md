Ryter in a container without git now says that git is missing, the question card no longer promises an undo it can't give, and a model looking for an installed program no longer stops on a question.

## Upgrade

```sh
ryter update
```

Coming from 0.44.0:

- **A missing git is said as missing.** In a container with no git, such as a fresh distrobox, a project cloned on the host read as "not a git repository" in `/undo`, `/storage`, `/changes` and the audit. The build turn's notice was a raw `io: git: No such file or directory`. Each now says git isn't installed here, so Ryter keeps no checkpoints until it is, and the notice comes once a session, not at every build turn.
- **The question card says what is at stake.** A command that only reads, such as `cat /etc/hostname`, says "only reads · changes nothing" instead of "runs a command that can change things". Where no checkpoint can be taken (no repository, or no git), the card says `/undo` can't put the change back instead of promising it.
- **Listing the installed programs runs without a question.** In the build hat, `ls`, `stat`, `readlink`, `realpath`, `test` and `du` on `/usr`, `/bin`, `/sbin` and `/lib` run unasked: they say what is installed and hold nobody's data. On a box with no Python, the model's `ls /usr/bin/python*` used to stop the turn on a card. Reading a file there still asks, and so do `/etc`, `/usr/local/etc` and `/usr/local/share`.
- **A script and its test are a suite.** With no `pyproject.toml`, `setup.py` or Makefile, `test*.py` files that `unittest` collects make `python3 -m unittest` the proposed test command (`pytest` beside a `conftest.py`). Before, the `test` tool found nothing and the model ran the tests by hand.
- **Prices keep their digits.** A rate like DeepSeek's $0.035 per million showed as $0.04 in the model picker, and `ryter models` printed `$0.8999999999999999/1.5`. Rates now keep up to four places.
- **Two wordings.** `ryter doctor`'s price check says what it priced (1k tokens in and 1k out on grok-4.6), so a fresh home doesn't seem to have spent a cent. The project trust card says a trusted project's `config.toml` can set hooks, which are commands Ryter runs, and that your gate rules stay yours.

## Why

0.44.0 was driven in four distroboxes: Debian 13, Arch, openSUSE Tumbleweed and Ubuntu 24.04. The installer, `ryter doctor`, the Landlock sandbox and a real fix on `deepseek/deepseek-v4.1-flash-1017` worked in all four. What didn't: Tumbleweed and Ubuntu ship without git, and Debian without Python. Listing the installed programs is your ruling on the gate. `DECISIONS.md` 2026-11-02.

## Good to know

- The plan, audit and scribe hats still refuse reads outside the project, the system's folders included. This change is the build hat's.
- Without git, edits are made with no checkpoint, as before. Install git in the container to have `/undo`, `/changes` and reviews.

## Tried before release

The full local check and CI on Linux and macOS. The gate replayed 1,439 real commands from past sessions, with no verdict changed. The real TUI with the simulated provider in all four distroboxes covered:

- the `test` tool on bare test files;
- the system listing with no card;
- the read-only card;
- two build turns without git, with one notice;
- `/undo`, `/storage` and `/changes` with and without git.

The new trust card was checked at 80×24 and 120×40.
