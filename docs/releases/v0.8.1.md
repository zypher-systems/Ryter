Ryter no longer turns a folder of projects into one git repository. Started in a folder like `~/workspace` that holds other projects' repositories, crew mode stops before it does anything and tells you to start in the project's own folder. Solo mode still edits, but doesn't set up git there. When the project cost is counted for a folder above the one you started in, the rail now says which folder.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What was wrong

- **Ryter made `~/workspace` a repository.** A crew session started there on 2026-09-28 ran `git init`. It committed the 68 files at the top as the starting point, sweeping 29 project repositories into one new repository. It also wrote `ROADMAP.md`, `DECISIONS.md` and `notes/` there. Ryter only refused to do this in the home folder and at `/`.
- **So the project cost looked stuck.** Every project inside `~/workspace` counted toward that one repository. The total was the same whichever project you started in, and nothing on screen said why.
- **A failed turn closed with "✓ answered"** under its error.
- **Two small things from the 0.8.0 review:**
  - A headless run told the model that the user's settings kept a page closed.
  - `load_skill` read a hidden file in a skill's folder if the model named it, though the skill's file list leaves hidden files out.

## What changed

- **A folder of projects is left as it is.** That's a folder that isn't a repository with commits, but holds repositories in its folders or one level further down (`clients/acme`).
  - **Crew mode** stops at your first message, before any model call, with nothing written. It names the repositories it found and says to start in the project's own folder: `cd alpha && ryter`, or `mkdir myapp && cd myapp && ryter` for a new one.
  - **Solo mode** still edits files, but doesn't set up git for `/undo` there, and says so.
  - **What doesn't count:** repositories inside folders that Ryter's first `.gitignore` leaves out (`node_modules`, `target`, `.venv`, caches). They stay out of the first commit anyway.
  - **If you do want one repository there,** run `git init` and make the first commit yourself. Ryter then works in it as usual.
- **The rail names where the project cost is counted** when that's a repository around the folder you started in. The line appears under `project`, for example `in ~/workspace`. The project column in the `$` drawer is named for that folder too.
- **A failed turn closes as `✕ failed`.**
- **Pages:** a headless run is told it's headless.
- **Skill files:** `load_skill` refuses a hidden file in a skill's folder.

This covers the part of the "What 1.0 means" item "Ryter only touches the project it was started in" about creating repositories.

## Tried before release

In the TUI with deepseek-v4.1-flash, in a scratch folder `hub` holding two repositories (`alpha` and `beta`) and a note:
- **First try:** the check was only in the git setup. It refused, and nothing landed. But before that, the lead had already written `ROADMAP.md`, `DECISIONS.md` and `notes/` into `hub`. It also offered to "re-route the task into `alpha/`", which the crew can't do. So the check moved to the start of a crew turn.
- **With the fix:** in crew mode, I asked "Add a file hello.py that prints hello."
  - The message came at once, and the turn closed `✕ failed · 0.0s`.
  - Nothing was spent.
  - `hub` still held only `alpha`, `beta` and the note.
- **Started in `alpha/src`:** the rail showed `project $0` with `in …hpad/hub/alpha` under it, and the `$` drawer's column read `project · alpha`.

Solo mode in a folder of projects, the headless page message and hidden skill files are covered by tests.
