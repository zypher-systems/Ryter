Approving is quicker and clearer: a card above the message box says what the call does and why, `⏎` allows it, `a` allows that kind of action for the session, and `n` denies. Menus show their keys where you read them, and the model picker searches from inside the panel.

## The approval card

When the build hat needs your yes, a card opens just above the message box. The chat stays readable behind it, and the card says:

```
what    edit  stats.js
why     The file is a single line of arrow-function exports, so I'll match that style.
risk    changes a file in your project · /undo puts it back
change  stats.js  +6 −0
        (the diff)
⏎ allow   a allow edits to files in the project this session   n deny
```

- **`⏎` allows.** An Enter pressed in the first half-second after the card opens is ignored, because it may have been meant to send a message.
- **`a` allows the kind of action the card names**, for the rest of the session: edits to files in the project, or `cargo test` commands. Other actions still ask. Before, `a` allowed everything, destructive commands included, which is why it took two presses.
- **`n` or `Esc` denies.**
- **Commands that delete, move, or discard files** (`rm`, `mv`, `git reset --hard`, `git clean`, deleting a branch) and **writes outside the project** take only **`y`**. Enter says so instead of approving, and there's no `a` for them.

The "why" is the model's own sentence just before it asked.

## Menus

- **Keys where you read them.** Every panel lists its keys on its last row, keys in color, instead of in dim text along the border. The bar at the bottom of the screen shows the same keys. It used to show form keys (`tab next field`) even on a permission prompt.
- **Search inside the picker.** In `/models` and `/help`, what you type appears in a search row at the top of the panel, above the list it filters, instead of in the message box at the bottom of the screen.
- **The model picker opens on the model you're using,** and dims models that can't use tools.

## Tried before release

In the TUI, on `deepseek-v4.1-flash`:

1. **"Add a median function."** The card opened above the message box. It showed the model's reason, the risk, and the diff, and `⏎` applied the edit.
2. **"Delete stats.js with rm."** The card was titled `approve? · press y`, and its risk read `deletes, moves, or discards files · /undo may not reach it`. `⏎` showed `Enter doesn't approve this one`, and `n` denied it. The file stayed.
3. **`mkdir -p build`, twice, then `touch build/x`.** `a` on the first `mkdir` covered the second, which ran without asking. `touch` asked.
4. **`/models`.** It opened with the cursor on `deepseek-v4.1-flash`, and typing `grok` filtered from the search row inside the panel.
5. **`/provider`.** It showed `openrouter · deepseek-v4.1-flash`.
