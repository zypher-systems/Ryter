Four things from the first session on 0.17.0: one spinner with the reasoning under it, more rounds a turn, a guide from the scribe, and an audit card whose Enter does the right thing.

## Upgrade

```sh
ryter update
```

From 0.8.2 or earlier, run the install script once:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

Coming from 0.17.0, these behave differently:

- **The activity strip above the prompt is gone.** The row under the model is the one place a turn's progress shows. `Ctrl+R`, or a click on that row, opens the reasoning right under it, in the conversation; the same closes it. After the turn the pane sits under the turn's receipt line. `[ui] reasoning` keeps its three values with the same meaning.
- **A turn may use 150 rounds** before it stops and asks you to continue, where it used 40. `rounds a turn` in `/settings`, `[limits] rounds` in config, or `--rounds N` for one run change it; `0` lifts the cap and leaves the spend budget as the guard.
- **The scribe, asked for documentation,** writes `README.md` and `docs/guide.md`, not the README alone.
- **On the audit card, Enter closes a pass and repairs a failure.** A card with no failing finding offers `⏎ close · n close`; one with a failure offers `⏎ repair in build · y repair in build · n close`.

## What was wrong

- **Two spinners at the bottom.** With the conversation scrolled to its end, the status row under the model and the strip above the prompt both spun, one over the other. The user called it distracting and asked to keep the one in the conversation.
- **Forty rounds was not enough for a small feature.** A build that reasons and edits across many files hit the cap and stopped, and the user typed "continue" again and again to let it finish.
- **The scribe wrote a README and stopped.** Asked for documentation, that is half of it; a project also needs a guide for its user or its operator.
- **The audit card offered to repair a pass.** `y` sent a clean audit to the builder, which makes no sense; and Enter, the key a hand reaches for, did nothing useful on either verdict.

## What changed

- **One spinner, and the reasoning under it.** The strip's rows are gone from the solo and classic screens. The reasoning pane is placed in the conversation: after the status row while the turn runs, after the receipt line once it has ended, with a header `reasoning · 1:40 · ^r close`, the text following its tail unless you scroll it, capped at a third of the column. `Ctrl+R` toggles it, and so does a click on the status row or on the pane's header. A turn with no reasoning stream still says so when the pane is opened, so the key always does something visible.
- **Rounds a turn.** `[limits] rounds = 150` by default; `0` for no cap; the `/settings` row applies to the running session and is saved; `--rounds N` for one run. The message when the cap is reached names the number and both places to raise it. The nudge and the stop on a call repeated with the same result are unchanged.
- **The scribe's documents.** Asked for documentation with nothing more specific, it writes `README.md` (what the project is, how to build and run it) and `docs/guide.md` (how to use it, and for a service how to operate it: configuration, running, upgrading), keeps either that already exists, says what it wrote and read, writes one document when one is asked for, and a CHANGELOG only when asked or when one exists.
- **The audit card's keys follow the verdict.** A pass: Enter and `n` close, `o` opens the file, `y` does nothing. A failure: Enter and `y` send the audit to the build hat as the repair brief, after the same half-second guard, `n` closes.

## Tried before release

- **The whole test suite** on Linux: 686 tests pass, with the acceptance suite and both benchmark steps. New ones cover the strip's rows gone from both layouts, the pane placed under the status row while busy and under the receipt after, its height cap, `Ctrl+R` and the click toggling it; the rounds cap read from config, `0` meaning none, the stop message naming the setting; the scribe's prompt naming both documents; the audit card's Enter on a pass and on a failure.
- **In a terminal, against a paced simulated provider:** one spinner in the conversation and none above the prompt; `Ctrl+R` opening the pane under `thinking · 0:02 · 30 tokens` with the reasoning filling it; after the turn the pane under `✓ answered · 4.3s`, and `Ctrl+R` closing it; a passing audit's card closing on Enter with the hat unchanged; a failing audit's card starting the repair turn in build on Enter.

### Fixed after review

The release PR's external review found two defects. Each fix has a test that fails on the reviewed code:

- **`--rounds` did not stay one run.** The flag was written into the loaded config, and every save of the settings (`/settings`, `/budget`, `/theme`, the receipt toggle) wrote that value to `settings.toml`, where it replaced `[limits] rounds` on the next launch. The flag now reaches the running session only; a save writes the loaded value, and the `/settings` row persists a number only once you edit it.
- **The workbench showed the reasoning twice.** That screen keeps its strip, and the new pane was placed in its chat column as well, so `Ctrl+R` opened both. The pane is not placed on the workbench; the strip is its one reasoning surface there.
