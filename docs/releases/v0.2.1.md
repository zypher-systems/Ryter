A fix release for 0.2.0. It has two fixes found in the first days of hands-on use. Upgrading is recommended, especially on Linux.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

This replaces the binary in place. Your keys, crews, settings, and sessions in `~/.ryter` stay as they are.

## Fixes

**On Linux, a key saved in 0.2.0 could be lost at the next reboot.** 0.2.0 saved keys to the system keyring and deleted the file copy. On Linux that keyring is the kernel's key store, which lives in memory and doesn't survive a restart. Keys on Linux now live in `~/.ryter/keys/<connection>`, readable only by you. The macOS keychain is unchanged.

- **If you saved a key in 0.2.0 and have since rebooted:** it's gone. Save it again (`/provider` → set-key, or `ryter connections set-key <name>`), and this time it will stay.
- **If you haven't rebooted:** save it again anyway, and it moves to the file.
- **If you use environment variables like `OPENROUTER_API_KEY`:** you weren't affected.

**The model can now offer to switch hats, and you can answer.** In solo mode the plan hat used to end with "want me to switch to build?", and there was no way to say yes. Now it asks with a yes/no prompt: "switch to the build hat: carry out the plan". Press `y` and it carries on building in the same turn; `n` keeps the plan hat. Review does the same when it finds things to fix. `Tab` still switches hats yourself.

## Also

- Ryter's own tests no longer write to your system keyring.
