## Edits show what changed

A `write` or `search_replace` row in the chat now shows the change itself:
- numbered lines, with the file's own line numbers;
- two lines of context around each change;
- added lines on a green row and removed lines on a red row, out to the edge of the chat, highlighted like the file.

A long edit shows its first 12 rows and says how many more there are. `^o` shows every edit whole, and `^o` again folds them. The line that closes a turn counts the real lines added and removed.

**Permission prompts for an edit show the change it would make**, the same way, before you say yes. The prompt used to show only the path. For `propose_edit`, which is meant to show the whole change, it cut the change at 160 characters.

In 16 colors and `NO_COLOR` the text carries the color, or the `+`/`-` sign alone.

## Turns that end

"The model keeps spinning" had several causes. Each is fixed:

- **Crew mode: a waiting patch cost 40 calls per message.** While a patch waited on a blocked task, the lead was handed the same "patch waiting" report after every reply, until the 40-round limit, at a paid call each. The lead now checks the crew once per message, unless it queues new work.
- **A stuck request never timed out.** OpenRouter's keep-alive messages reset the idle timer, so a request stuck in a provider's queue waited for good. Five minutes with nothing but keep-alives now ends the turn with an error that says so (15 minutes for a local server).
- **A finished reply could still hang.** After the provider's end-of-reply message, Ryter waited for the connection to close. On a server that kept it open, a finished answer failed after two minutes. The reply now ends at the provider's word.
- **Provider errors looked like empty answers.** An error sent in the middle of a reply (an overload, an upstream failure, a content filter, a full context window) now ends the turn as an error that names it.
- **Esc during a command broke the session.** The model's tool calls were left without results, and every later message was rejected by the provider. Every call now gets an answer, and a session broken this way is repaired on its next message.
- **The same failing edit ran to the round limit.** When the model makes the same call and gets the same result a third time, it is told to change approach. The fifth time, the turn stops and the chat says why.
- **The round limit was silent.** It now says it stopped, and that "continue" carries on.
- **Esc and `^c` didn't reach an open prompt.** A turn waiting on a permission or a question kept waiting for up to five minutes. It now stops at once, and `^c` on a prompt stops the turn.
- **`git commit` without `-m` waited for vi.** Commands now run with no editor, pager, or password prompt to wait on. They also run without Ryter's own API keys in their environment.
- **A failed `search_replace` gave the model nothing to go on.** A miss now says where the text probably is and what to re-read. A repeat says which lines matched. An edit that changes nothing is refused. Files with Windows line endings now match.

Also fixed:
- A character split between two network packets was corrupted, including inside the content of a file the model wrote.
- Anthropic models' input tokens were left out of spend.
- A crew task interrupted by a quit stayed "running" for good, and held its patch.

## The shell gate

**The never-run list** (`sudo`, `ssh`, `dd`, `mkfs`, `systemctl`, `crontab`, …) could be passed with:
- a wrapper's options: `env -i sudo`, `timeout 5 sudo`, `nice dd`, `xargs -0 ssh`;
- an escape: `s\udo`;
- a name built at run time: `$(echo sudo) ls`, `$X ls`, `eval`;
- a command run by another: `find -exec sudo`, `fd -x`, `busybox rm`, `git -c alias.x='!sudo …'`.

These are refused now, in every hat. Git settings that name a program, such as `core.sshCommand` and `core.pager`, are refused as well.

**The review hat is judged by the form of a command, not the tool's name.**
- It runs: `cargo test`, `cargo clippy`, `cargo fmt --check`, `npm test`, `npm run lint`, `npx vitest run`, `npx tsc --noEmit`, `pytest`, `ruff check`, `go test`, `make test`, and the like.
- It doesn't run: `cargo fmt`, `npm install`, `npm run format`, `npx <any package>`, `ruff --fix`, `make install`, `pip install`. It used to run all of them, without asking, in your own tree.

**Read-only commands in forms that run or write are no longer read-only:** `sort --compress-program`, `rg --pre`, `git grep -O`, `yq -i`, `git diff --output`. Bare `env`, which prints every secret in the environment, isn't read-only either.

**What you may notice:**
- `node -e`, `deno eval`, and `bun -e` are refused in every hat, as `python -c` already was: the gate can't read inline code. Write it to a file and run the file.
- In plan and review, `wc -l $(git ls-files)` is refused, because the files inside `$(…)` can't be checked first. The refusal suggests `git ls-files | xargs wc -l`.
- A crew builder that deletes files through `xargs`, or after a `cd` out of its worktree, is asked instead of let through.

The never-run list slows a builder down; it doesn't bind one. A builder can still write a script that runs anything. The Landlock sandbox is the boundary for that (`ryter --sandbox workspace`).

## Tried before release

In the TUI, on `deepseek-v4.1-flash` over OpenRouter:

1. **An edit and a new file.** "Make `/search` trim the query and add tests." The edit to `server.js` showed as numbered rows (`+10 −2`), with the real terminal drawing the added rows on a green tint. The new test file showed as `new · 32 lines`, folded after 12 rows. `^o` showed both whole.
2. **An edit prompt.** "Change the port to 8080" asked with the diff: line 16, `app.listen(3000)` on red and `app.listen(8080)` on green. `y` applied it.
3. **Esc mid-command, then carry on.** `sleep 45 && echo finished` stopped 3 seconds after Esc. The next message was answered normally, and every tool call in the saved session had its result.
4. **The review hat.** It ran `npm test` (1 passed). It didn't run the format, install, or `node -e` steps, and offered to switch to build for them. The working tree stayed clean.
