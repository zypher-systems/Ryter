Review and commit without leaving Ryter: see what changed, undo a single file, and commit with a drafted message and a receipt of what the change cost.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## `/changes`

Every changed file, with its diff, file by file. You can compare against two points, and `Tab` switches between them:

- **Uncommitted:** everything since your last commit. This is what `/commit` would commit.
- **Last turn:** only what the latest build turn changed.

Keys:
- `↑↓` picks a file, and `PgUp`/`PgDn` scroll its diff.
- `x` puts one file back as it was, deleting it if the file is new. Ryter takes a snapshot first, so `/undo` brings it back.
- `c` goes on to `/commit`.

New files are included, and looking never touches your staging area.

## `/commit`

1. **Pick the files.** All uncommitted files are ticked; `space` unticks one.
2. **Check the message.** The model has already drafted it from:
   - the diff;
   - your project's recent commit subjects, so it follows your style;
   - the conversation, including its narration of why it made each choice.
3. **Edit if you want.** `e` edits the message in the message box. `d` asks for a new draft.
4. **Commit.** `Enter` commits only the ticked files, with your git identity and your hooks. Anything you'd staged yourself stays out of this commit.

## The receipt

With receipts on, each commit ends with a line saying which models did the work, what it cost, and whether the tests passed:

```
Ryter: deepseek-pro-latest · $0.34 · tests ✓ 13 passed
```

- **The cost** is what this project spent since the previous commit, across every session. It says `$0.34+ (some prices unknown)` when a model had no known price.
- **The tests** are the latest run's result. The receipt doesn't claim a pass it can't back up: it says `tests not rerun after the last edit` if the model changed files after that run, or `no tests run`.

Receipts are on by default. You see the line before you commit, `t` turns it off, and the choice is remembered as `[ui] receipts`. Find the commits later with `git log --grep "Ryter:"`.

## Also

- **`/undo` counts files correctly.** It said "3 files" after putting back one; it now counts from a diff.
- **The model knows about `/changes` and `/commit`.** The solo prompt tells it the user reviews and commits there, which is one more reason to narrate its choices.

## Tried before release

In the TUI, on `deepseek-pro-latest`, in a fresh repository:

1. **The build.** Ryter wrote a small temperature module with node:test tests: 3 new files, `✓ 5 passed`.
2. **`/changes`.** It listed the 3 files (`+42 −0`) with colored diffs. In the last-turn view, `x` deleted `temp.js`, and the view still listed the turn's 2 other files.
3. **`/undo`.** It brought `temp.js` back.
4. **`/commit`.** The draft was "Add temperature conversion utilities and tests". The commit landed with `Ryter: deepseek-pro-latest · $0.01 · tests ✓ 5 passed`.
5. **A second change.** After a follow-up that added Kelvin, `e` opened the drafted message for editing. The edited message was committed with its receipt (`$0.02 · tests ✓ 6 passed`), and the working tree was clean.
6. **The receipt switch.** `t` wrote `receipts = false` to settings.toml, and `t` again wrote it back to `true`.
