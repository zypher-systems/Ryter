A turn no longer hangs when a command leaves a server running.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/ryter/main/install.sh | sh
```

## What was wrong

A build would finish its work, but the spinner kept going and the turn never ended. The cause was the model's last command:

```sh
(PORT=3210 node server.js &) && sleep 1.5 && curl -s http://localhost:3210/api/reports; pkill -f "PORT=3210"
```

The `pkill` was meant to stop the server. It matched the command's own shell instead, because environment variables aren't part of a process's command line. The server kept running and kept the command's output open, and Ryter waited for that output to close. It never did: not at the timeout, and not until you pressed Esc.

## What changed

- **A command returns when its shell exits.** Anything it left running in the background is stopped. The output ends with `[stopped the background processes this command left running]`, so the model knows the server is gone.
- **A process that detaches completely can't keep a command open.** This covers a process started with `setsid`. After half a second the command returns whatever it printed, with a note.
- **Commands with a lot of output no longer stall.** Anything over 64 KB, such as a verbose build log, used to wait out its whole timeout. Output is now read while the command runs.
- **Esc and timeouts stop everything a command started.** Stopping a command now sends the kill through bash rather than `/usr/bin/kill`. On Ubuntu (procps-ng), `/usr/bin/kill` didn't reliably reach a command's background processes.
- **The model is told the rule.** The bash tool says background processes stop when the command returns, so a server should be started, tested, and stopped in one command.

If you want a dev server to keep running, start it yourself in another terminal.

## Tried before release

In the TUI, on your model (`deepseek-pro-latest`), the build hat was given the exact command from the stuck session, with a small node server:

- **v0.2.5:** still stuck on the command at 2:37, past its 120-second timeout, with the spinner running.
- **v0.2.6:** the command returned in about 2 seconds with the server's reply and the "stopped" note. The model explained why `pkill` misfired, and the turn closed with `✓ done`. No server was left running.
- **Esc on v0.2.6:** pressed during a long command that had started a background job. Both stopped.
