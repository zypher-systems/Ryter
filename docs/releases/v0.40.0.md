Six changes to what the model is handed and held to, so that the same model finishes with fewer redos: a test run comes back as its failures, a map of the project and Ryter's own notes on it open every session, the choices made in the work are recorded beside the plan, a rewrite needs a read, and a build turn does not end on "done" while the project's check fails.

## Upgrade

```sh
ryter update
```

Coming from 0.39.0:

- **A test run reaches the model as its failures.** `run_project test`, the check after edits and a `bash` test run too long to keep whole hand the model each failed test with its assertion and where, and the runner's totals, for cargo test, go test, pytest, unittest, jest, vitest and mocha. The last sixty lines, which is what it used to get, carried the names and the totals and not the assertion, and the model spent a round running one test again to read it. A run that passed is its totals line; a runner Ryter does not recognise still comes back as its last lines.
- **The project map.** When a session's first turn begins, the model and the scout are handed the project's folders and the signatures of its Rust, Python, TypeScript, JavaScript and Go files: public functions, types, classes and their methods, exports; other source files named, data files counted. It goes to the file instead of listing and reading to find it. Signatures only, no bodies and no line numbers, so a file is still read before it is edited. Held for the session, so the prompt's cached prefix survives the model's own edits, and remade when the conversation is compacted. `[map] chars` in `config.toml` bounds it (12,000; `0` leaves it out); hidden folders, what `.gitignore` names, and build output and installed packages are not in it.
- **Decisions beside the plan.** `record_decision` now also records the choices made in the work, a library, a data model, a structure, a workaround, and what you decide when the model asks, under `## work` in `.ryter/decisions.md`, no plan needed. Every hat is shown the file's entries at the start of a session, so a later session or another hat builds on what was decided instead of deciding again, and the audit's brief points at them. The file stays yours to edit.
- **Ryter's own notes on the project.** From what happened, never from what the model said: the commands that ran here (project verbs, slow commands, the run file's own) with how they came out, how long they take and which runner is not on this machine, and the last five sessions with their title, turns, edited files and whether the check was passing at the end. Kept in Ryter's home as `projects/<project>.observed.json`, not in the project, and shown to the next session at its first turn.
- **A rewrite needs a read.** `write` over an existing file is refused unless the model has read the file as it is now: never read this session, or changed since the model last read or edited it, by you in your editor, by a formatter, by a command. The tool says which and tells it to read first or use `search_replace`; a `search_replace` whose lines are not found says plainly when the file changed since the read. Your edits between turns are never overwritten unread.
- **Done means checked.** In the build hat, the model's "done" with the run file's check still failing is not the end of the turn. The chat says `not done: cargo check still fails · round 1 of 3`, the failures go back to the model, and the turn ends when the check passes, when the model says in a line starting `Blocked:` what is in the way (the chat shows it), or after `[limits] check_rounds` such rounds (3; `0` turns it off). The fast check alone, not the test suite; a check whose program is not on this machine is not held against the model; and nothing about the gate changes: what asked before still asks.

## Why

A harness does not make a model smarter. It can stop the model guessing what the harness already knows, and make what it hands back small, exact and true. Each of these six removes a guess or a redo seen in the bench's hard tasks: the assertion that was in the output all along, the file found by listing three folders, the choice re-decided by the next session, the test suite's duration rediscovered, the user's edit rewritten from memory, the confident summary one round before the fix.

## Good to know

- The map keeps no default values (`def connect(password=…)`) and does not read or name a path the gate holds secret (`.env`, a key file, a credential path); its root line honours `.gitignore` like the rest. A test digest with more totals lines than fit keeps the failing ones; `cargo test -- --show-output` blocks of passing tests are not counted as failures. A read whose offset is past the end of the file is an error and does not count as having read it.
- The map, the notes and the decisions all go into the system prompt. The map and the notes are held for the session for the prompt cache; the decisions file is read each turn, so a recorded decision costs one cache miss.
- `.ryter/decisions.md` has a new header paragraph and a `## work` section; the plan sections are as before, and an older file reads as it did.
- The notes live in Ryter's home, `projects/<slug>.observed.json`. A session is not shown its own note. Twelve commands and five sessions are kept.
- The refusal of an unread rewrite applies to the model's `write` tool only; a shell redirect is the gate's business as before. A new session, `/new` included, starts with nothing seen, so the first rewrite of each file needs a read; what the scout read does not count as the hat having read it.
- A command's output is captured whole up to a megabyte while it runs, so the failures digest sees a failure in the middle of a long test run; the tool result the model gets is still cut to 32,000 bytes after, with the digest in front.
- A command that carries what looks like a secret (a password or token in an option or an assignment, an auth or cookie header, a key by its shape) is not written into Ryter's notes. A shell's "not found" (bash's and dash's) counts as a program missing on this machine; a program's own "not found" is a failure.
- Done means checked holds only where an approved run file has a `check`. Headless runs (`ryter -p`) and the bench get the same loop, which is what makes its effect measurable there.
- A test in the cancelled-check path cancelled after a fixed wait and flaked on CI once the first turn builds the map; it now cancels when the check starts.
- Open from earlier releases: the scout has no seat in `/models`; the live measurement of check rounds avoided; the `/sessions` panel's columns; selecting with the mouse untried by a person; the bench on macOS.

## Tried before release

The full local check and CI on every patch. The real binary driven offline for each piece: a failing test run reaching the model as its assertion with the chat row carrying the totals; the map in the first request's prompt and in the scout's, with the root's own source files mapped; a choice recorded under `## work`, the chat's "decision recorded" row, and the next turn's prompt carrying it; two sessions through `/new`, the second told what the first ran, edited and left failing; a rewrite refused until the model read the file, your edit between turns kept; a build turn going on past "done" until the check passed.
