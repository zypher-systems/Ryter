The project's verbs as tools, so the model stops guessing commands the harness already knows: `test` narrows to a name or to the files it edited with the runner's own flag, `build`, `check`, `lint` and `format` run the project's own commands from the run file, a project with no run file has its verbs read from its manifest for you to approve, and the hard bench level grows to ten tasks.

## Upgrade

```sh
ryter update
```

Coming from 0.40.0:

- **`test`, with a name or with files.** The model runs the project's tests with a tool of that name, from the run file you approved. `filter` runs the tests whose name matches and Ryter adds the runner's own flag (cargo test's positional name before a `--`, pytest `-k`, go test `-run`, jest, vitest and bun test `-t`, mocha `--grep`), through `npm test`, `pnpm run`, `yarn`, `npx`, `uv run`, `poetry run` and `python -m`, with a `package.json` script read to find the runner behind it. `files` runs the tests that cover those files: a Cargo file as its package (`-p`, with `--workspace` dropped so it is heard), a Python or script source as the test file named for it, a jest file through `--findRelatedTests`, a Go file as its directory. The model gets the digest under the command as it ran, a line for each file the run does not cover, and a last line saying the whole suite has not run; a name that matched nothing is said in words. A command Ryter can't narrow (`make test`, several commands in one) is listed as not run rather than run whole under a narrow name. The chat row names the command as it ran.
- **The edited files' tests first.** A bare `test` in the build hat, with files edited this session, runs their own tests first and the whole suite only once those pass. A failure comes back in seconds under the names the model just touched, with the whole suite not run, said in the last line. The chat row names both commands. The audit hat runs the whole suite whatever was edited.
- **`build`, `check`, `lint`, `format`.** The run file gains `build`, `lint` and `format` beside `check`, proposed and approved like the rest, and each is a tool of that name. `build`, `check` and `lint` come back as the check's report: the errors as the compiler or linter printed them, capped, or one word (`built`, `passed`, `clean`). `format` runs the formatter over the project and comes back with the files it changed, read from the project before and after by content, and those files count as the round's edits: the check runs after them and the session's notes carry them. `format` is the build hat's alone; the audit changes nothing. The chat shows each as its own row with the word or the count.
- **No run file: the manifest is read for you.** A verb in a project with no run file no longer sends the model off to read the project and propose one. Ryter reads the manifest at the root (`Cargo.toml`, `package.json` with its scripts and lockfile, `go.mod`, `pyproject.toml` and its tools, a `Makefile`'s targets) and puts the commands it found on the approval panel with a note naming the file. A yes saves them as the run file and the verb runs in the same call; a no leaves things as before. The product's `start`, `ready` and `stop` are never guessed.
- **Ten hard bench tasks.** Six more at `level = "hard"`, two per language: `config-interpolation` and `rate-limiter` (Python), `rust-lru-ttl` and `rust-glob` (Rust), `ts-json-patch` and `ts-cron` (TypeScript), each with a reference the runner proved. Ten tasks at each level, so a solve-rate step is ten points instead of twenty-five. `ryter bench --level hard` and `/benchmark` run them.

## Why

The build hat ran most tests through `bash`, guessing the runner, its filter syntax and the directory, and a guess that missed cost a round; a guess that ran the whole suite to look at one test cost minutes and a wall of output that was then cut. The run file the user approved named the runner all along. The same holds for the build, the linter and the formatter, and for a project whose manifest says in plain terms what the model was about to spend a round reading. Each verb is one guess the model no longer makes and one answer that comes back small, exact and true.

## Good to know

- `run_project test` and `run_project check` still work and run the same code as the new tools, as a whole run; old transcripts and the simulated bench use them. `run_project` keeps `start`, `stop` and `status`.
- A narrowed test run does not count as the project's check: `last_check`, the notes and done-means-checked read whole runs only. A narrowed run is not written into Ryter's notes either.
- The runner is never swapped for another program: `npm test` stays `npm test -- -t name`. A cargo filter is a substring of the test's path; go's `-run` is a regex. Cargo files map to `-p` only, not `--test`, `--lib` or `--bin`.
- A source file maps to the test named for its whole stem (`button.component.ts` to `button.component.spec.ts`), the one beside it first. When files are given, a test folder the command itself names (`pytest tests`) is dropped so the run is really the files' tests; a path or pattern in the command that is not a folder here, or a `package.json` script that names paths itself, can't be narrowed by files and says so (a filter still works). Go's flag values are kept and every package word gives way to the files' directories.
- `format` changes files, so it checkpoints like a write and `/undo` covers it. After a format the model is told to read a file again before editing it, since a rewrite of a file changed since it was seen is refused.
- The run file's new fields are optional; an older file reads as it did. The approval panel shows `build`, `lint` and `format` rows; `propose_run` takes them. `.ryter/run.toml`'s header comment names them.
- Detection runs only for the verbs, only with a user present, and only when there is no run file at all; `run_project start` is untouched. A detected file that no hat could run falls back to the old message. A project with both a manifest and a `Makefile` takes the manifest.
- The ten-hard-tasks commit reached `dev` with CI red: a TUI test counted four hard tasks. Fixed in the next commit; the release commit's CI is green.
- Open from earlier releases: the scout has no seat in `/models`; the live measurement of check rounds avoided; the `/sessions` panel's columns; selecting with the mouse untried by a person; the bench on macOS. New: lint and format scoped to files; cargo `--test <name>` for a file directly under `tests/`; a live hard-level run.
