# Next

Unreleased: what is in `dev` since 0.19.0. These notes become the next release's `vX.Y.Z.md`.

## What changed

- **A file of the turn's own is deleted without a card.** Deleting a file or folder of the command's own in scratch space (`rm -f /tmp/cookies.txt`, `find /tmp/probe -name '*.log' -delete`), or a file this turn made (a `write` of a new file, a redirect, `touch`, `cp`, `mkdir`), runs in the build and audit hats without asking: the turn's checkpoint holds neither, so a question protected nothing. `cat > probe.sh; sh probe.sh; rm probe.sh` runs whole. Still asked: scratch space itself or everything in it (`rm -rf /tmp`, `rm -rf /tmp/*`), a repository in scratch space, the user's folder, the project's own files, a file made in an earlier turn, and a glob or a value the shell fills in.
- **Naming a secret is not reading it.** A secret's name in a search pattern or a `sed`/`awk` script (`grep -E '\*\.pem|\*\.key' .gitignore`, `sed -n '/\.env/p' .gitignore`), or handed to `git check-ignore` or `git check-attr`, runs in every hat. The file named is still the file read: `grep KEY .env`, `grep -f .env x`, `git show HEAD:.env` are refused as before. A pattern that reads as an absolute path (`grep -o '/assets/[^"]*\.css'`) no longer asks as a read outside the project either.
- **`git remote -v`, `show` and `get-url` are looks.** They print the remotes and run in every hat; `add`, `set-url`, `remove`, `rename`, `prune` and `update` ask in the build hat and are refused in the others, as before.
- **The audit's refusal of `write` says what the audit may do.** It names `audit.md` as the audit's one file, says a probe or a fixture goes through `bash` in the project or `/tmp` and is put back with the checkpoint, and that a lasting change is the build hat's. It used to say "the audit changes nothing" while the audit's shell commands wrote probe scripts behind the checkpoint all along.
- **A session's asks are in its log.** `events.jsonl` has an `asked` line beside each tool call that put a permission card up: the card's title, what it asked, whether only `y` would do, the answer (`allow`, `always`, `deny`, `none`) and how long the person took. Every `tool_call` and `turn_started` line carries `at` (milliseconds since the Unix epoch), and a `tool_call` its `turn`. Old logs read as before. The same fields are on the `--json` stream.

## Why

From the user's first real run on 0.19.0 (2026-10-04/05): an expense tracker (Fastify, Vite, Postgres) taken through plan, build, audit, repair and scribe, then dark mode through the same, for $2.67. The flow held; the log held no asks, so the run's 156 shell commands were replayed through the gate. Dev's gate asked 24 times and refused 5; eighteen of the asks were the model deleting cookie jars in `/tmp` and probe scripts it had written moments before, and three of the refusals were a secret's name in a pattern or in `git check-ignore`, one of which ended a twelve-line audit script. The same replay through this gate asks 18 times and refuses 2 (`sh -c '…'`, and `touch /tmp/tls_test.key`, a key-named file, which stays refused). Of the 18, fourteen are one rule not decided here: a `$(date +%s)` inside `curl`'s quoted data, read as a file the gate cannot see; three are probe deletions a replay cannot credit to the turn that made them; one is `git push`.
