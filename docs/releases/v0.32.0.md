Cache reads and cache writes are priced at their own rates for every model, the provider's own figure wins where it gives one, and a model the tables never heard of is priced from a catalog pulled once a day.

## Upgrade

```sh
ryter update
```

Coming from 0.31.0:

- **The cached rate is never lost.** The first Anthropic run on 0.31.0 billed every prompt token at the input rate: a turn that read 26,478 of its 27,691 tokens from the cache cost $0.06 and showed $0.16. The sidebar's model list, which knows input and output only, had been laid over the shipped row that knew the cached rate. A list now fills in a model the book does not know and never undoes a cache discount. Every connection was affected the same way.
- **Tables read against the price pages.** Every Claude and GPT row was checked on 2026-10-19. Cache writes are five quarters of input at Anthropic and at OpenAI from GPT-5.6 on; Fable 5 reads at $1 per million and Sonnet 5.5 at $0.10, which the old table had wrong. A dated Claude id prices as its model.
- **The provider's own figure wins.** OpenRouter's cost arrives on every stream and SpaceXSI's `cost_in_usd_ticks` on every response; both are read, so those turns are priced to the tick.
- **Writes are counted everywhere.** OpenAI's and OpenRouter's cache-write counts are parsed. The ledger, `ryter spend`, the spend panel and its CSV show cached reads and cache writes side by side, so a turn can be checked against the provider's console. Below 56 columns the panel drops the written column to keep the dollars on screen.
- **A price catalog for models nobody ships.** Once a day at launch, on its own thread, Ryter pulls the public [models.dev](https://models.dev) list into `~/.ryter/prices.json`: input, output, cache read and cache write under each provider's own ids. It prices a model that appeared after this release; the shipped tables still win for a model they know and stand alone offline. `[spend] catalog = false` turns the pull off, and `ryter doctor` reports the catalog's size and age.

## Why

Cost reporting is only worth having when it matches the invoice. The merge rule is the fix; the verified tables, the provider's own cost and the written count are what let anyone check a turn against the console; the daily pull is for the model that arrives between releases.

## Good to know

- The pull is a plain GET of a public file. No key, no session and nothing about your project goes with it.
- Ledger lines written before this release are not re-priced; the sessions that showed the fault keep their figures.
- Anthropic's one-hour cache (twice the input rate to write) is not used by Ryter, so it is not priced. A cache write on Grok is billed as plain input, as xAI's page gives no rate for it, and the provider's own cost wins anyway.
- No live turn was made on each wire against the provider's console before this release; a turn on your own key and a look at the console beside `ryter spend` is the first thing to try.
- The two 80-column edges from 0.30.0 are still there: the top bar's title runs into the status text, and the hint bar never shows `^c` or `esc`.
